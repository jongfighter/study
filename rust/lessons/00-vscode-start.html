    LESSON 00 · VS CODE 첫걸음

    VS Code 첫걸음

    코스 폴더를 VS Code로 열고, 화면 구성·명령 팔레트·빠른 열기·설정·단축키 편집기를 직접 눌러 보며 익힙니다. 이 레슨이 끝나면 마우스 없이 파일을 열고, 터미널을 켜고, 설정을 바꿔 볼 수 있습니다.

    • 소요 약 60분
    • 난이도 ★☆☆☆☆
    • 선행 없음 (VS Code 설치 완료)
    • 실습 폴더 D:\study\rust

    GOAL학습 목표

    • VS Code 화면의 다섯 영역(활동 막대, 사이드바, 에디터, 패널, 상태 표시줄)을 이름으로 가리키고, 각각을 단축키로 켜고 끌 수 있다.
    • "폴더 열기"로 코스 폴더 D:\study\rust를 열고, 신뢰(Workspace Trust) 확인과 권장 확장 설치를 처리할 수 있다.
    • 명령 팔레트(Ctrl+Shift+P)와 빠른 열기(Ctrl+P)로 명령과 파일을 이름만 입력해 찾을 수 있다.
    • 설정 화면에서 값을 바꾸고 그 결과가 settings.json에 기록되는 것을 확인하며, 사용자 설정과 워크스페이스 설정의 차이를 설명할 수 있다.
    • 통합 터미널을 열고 터미널 프로필(PowerShell, bash)을 고를 수 있으며, 단축키 편집기에서 원하는 단축키를 검색할 수 있다.

    READ먼저 알아 둘 것: 화면 구성과 용어

    VS Code는 "폴더"를 단위로 일하는 편집기입니다. 폴더를 열면 그 폴더의 파일 목록이 탐색기에 나타나고, 설정(.vscode)과 통합 터미널의 시작 위치가 그 폴더를 기준으로 정해집니다. 공식 문서(User interface, 영문)는 화면을 여섯 영역으로 설명합니다. 이 코스에서는 앞의 다섯 영역을 주로 씁니다.

    영역 (영문)위치하는 일켜고 끄는 단축키
    활동 막대 (Activity Bar)맨 왼쪽의 세로 아이콘 줄탐색기, 검색, 소스 제어, 실행 및 디버그, 확장 보기를 전환합니다.Ctrl+Shift+E Ctrl+Shift+F Ctrl+Shift+G Ctrl+Shift+D Ctrl+Shift+X
    사이드바 (Primary Side Bar)활동 막대 바로 오른쪽활동 막대에서 고른 보기의 내용(예: 파일·폴더 목록)을 보여 줍니다.Ctrl+B
    에디터 (Editor)가운데의 가장 넓은 영역파일을 탭으로 열어 편집합니다. 가로·세로로 나란히 열 수도 있습니다.Ctrl+\ (분할)
    패널 (Panel)에디터 아래터미널, 문제, 출력, 디버그 콘솔이 들어 있습니다.Ctrl+J (패널), Ctrl+` (터미널)
    상태 표시줄 (Status Bar)맨 아래 가로 줄커서 위치(줄·열), 언어 모드, 알림 종 아이콘, 폴더가 제한 모드일 때의 배지 등을 보여 줍니다.없음 (눌러서 사용)
    보조 사이드바 (Secondary Side Bar)에디터 오른쪽(사이드바의 반대편)공식 문서 기준 기본으로 채팅 보기가 들어 있습니다. 이 코스에서는 쓰지 않으며, 열려 있어도 닫아도 됩니다.Ctrl+Alt+B

    화면 맨 위에는 메뉴 표시줄(File, Edit, Selection, View, Go, Run, Terminal, Help)이 있습니다. 메뉴가 보이지 않으면 Alt 키를 눌러 보세요(window.menuBarVisibility 설정이 toggle이면 Alt로 나타납니다).

    꼭 구분해야 할 용어

    용어뜻
    폴더 열기 (Open Folder)폴더 전체를 작업 공간으로 엽니다. 탐색기에 구조가 보이고, 그 폴더의 .vscode 설정이 적용되며, 터미널이 그 폴더에서 시작합니다. 이 코스는 항상 이 방식으로 엽니다.
    파일 열기 (Open File)파일 하나만 엽니다. 폴더 문맥이 없으므로 코스 설정이 적용되지 않습니다.
    워크스페이스 (workspace)보통 지금 열어 둔 루트 폴더를 가리킵니다. 폴더 여러 개를 한 창에 여는 "다중 루트 워크스페이스"도 있지만 이 코스에서는 쓰지 않습니다.
    명령 팔레트 (Command Palette)VS Code의 거의 모든 기능을 이름으로 찾아 실행하는 입력창입니다.
    빠른 열기 (Quick Open)파일 이름을 입력해 바로 여는 입력창입니다.
    통합 터미널 (Integrated Terminal)패널 안에서 동작하는 터미널입니다. 어떤 셸을 쓸지는 "터미널 프로필"로 정합니다.
    제한 모드 (Restricted Mode)신뢰하지 않은 폴더를 열었을 때 코드 자동 실행을 막는 상태입니다. 터미널, 작업, 디버깅, 워크스페이스 설정, 일부 확장이 제한됩니다.

    HANDS-ON따라하기

    10단계를 순서대로 따라 합니다. 각 단계는 앞 단계에서 연 폴더와 열린 파일 위에서 이어집니다. 영문 메뉴 이름은 VS Code 기본 표시 언어(영어)를 기준으로 적었습니다.

    1. 폴더 열기 (앞 단계 없음)

      VS Code를 실행하고 메뉴 File > Open Folder...를 누릅니다(Ctrl+K Ctrl+O). 폴더 선택 창에서 D:\study\rust를 고르고 선택 버튼을 누릅니다. 파일 열기(Ctrl+O, Open File...)와 헷갈리지 마세요. 파일 열기는 파일 하나만 엽니다.

      이렇게 보이면 성공왼쪽 탐색기(Explorer) 맨 위에 폴더 이름 RUST가 보이고, 그 아래에 lab, lessons, README.md 같은 항목이 보입니다. 위쪽 창 제목에도 폴더 이름이 표시됩니다.
    2. 신뢰(Workspace Trust) 처리하기 (1단계에서 연 폴더)

      새 폴더를 열면 VS Code는 안전을 위해 먼저 제한 모드(Restricted Mode)로 열 수 있습니다. 화면 위쪽에 Restricted Mode is intended for safe code browsing. Trust this folder to enable all features. 배너가 보이거나, 상태 표시줄에 제한 모드 배지가 보이면 아직 신뢰하지 않은 상태입니다. 배너의 Manage 링크나 상태 표시줄 배지를 눌러 신뢰 화면을 열고 이 폴더를 신뢰합니다. Do you trust the authors of the files in this folder?라는 질문 창이 뜨면 Trust Folder & Continue를 고릅니다.

      이 코스 폴더는 직접 만든 코드와 공개 저장소를 클론한 자료로 이루어져 있으므로 신뢰해도 됩니다. 다만 질문 창에 "부모 폴더의 모든 파일 작성자를 신뢰"하는 체크 상자가 있다면 체크하지 마세요. 공식 문서에 따르면 부모 폴더를 신뢰하면 그 아래 모든 하위 폴더가 신뢰되어, 같은 부모 폴더의 다른 프로젝트까지 신뢰하게 됩니다.

      신뢰하지 않으면제한 모드에서는 터미널, 작업(tasks), 디버깅, 워크스페이스 설정이 제한되고, 확장은 지원을 선언하지 않았다면 꺼집니다. rust-analyzer 확장은 제한 모드에서 동작하지 않도록 만들어져 있습니다(확장이 "악의적인 설정으로 임의의 코드를 실행할 수 있다"는 이유로 지원 안 함을 선언). 신뢰하지 않으면 자동 완성과 디버깅이 꺼진 채로 남습니다. 나중에 바꾸려면 명령 팔레트에서 Workspaces: Manage Workspace Trust를 실행합니다.

      VS Code 1.146 기준 공식 문서는 기본 설정(security.workspace.trust.startupPrompt이 never)에서는 질문 창 대신 배너로 알린다고 설명합니다. 이미 신뢰한 폴더 아래의 폴더를 열었다면 아무 알림도 뜨지 않을 수 있습니다. 상태 표시줄에 제한 모드 배지가 없으면 신뢰된 상태입니다.

    3. 권장 확장 설치하기 (2단계에서 신뢰한 폴더)

      Ctrl+Shift+X로 확장(Extensions) 보기를 열고 검색창에 @recommended를 입력합니다. Workspace Recommendations 묶음에 이 폴더의 .vscode/extensions.json이 권하는 확장이 나타납니다. 각 항목의 Install 버튼을 누릅니다. 화면 오른쪽 아래에 권장 확장 설치를 안내하는 알림이 떴다면 그 알림의 버튼으로 설치해도 같습니다.

      확장 ID이름용도
      rust-lang.rust-analyzerrust-analyzerRust 공식 언어 서버 확장. 자동 완성, 정의로 이동, 오류 표시, 실행·디버그 버튼을 제공합니다.
      tamasfe.even-better-tomlEven Better TOMLCargo.toml 같은 TOML 파일의 색상, 자동 완성, 서식 정리.
      ms-vscode.cpptoolsC/C++Windows에서 Rust 실행 파일을 디버그할 때 쓰는 디버거(레슨 02, 09~11에서 사용).
      humao.rest-clientREST Client.http 파일에 적은 요청을 편집기 안에서 보냅니다(레슨 11 이후 사용).

      rust-analyzer와 Rust 도구(rustup, cargo 등)의 확인은 레슨 01에서 합니다. 지금은 확장만 설치해 둡니다.

      이렇게 보이면 성공검색창에 @installed를 입력했을 때 위 확장들이 목록에 보입니다. 설치한 확장은 내 PC의 VS Code 전체에 적용되며, 이 폴더에만 한정되지 않습니다.
    4. 명령 팔레트로 워크스페이스 설정 열기 (열린 폴더 필요)

      Ctrl+Shift+P를 눌러 명령 팔레트를 엽니다. 입력창에 workspace settings json을 입력하면 목록이 좁혀집니다. Preferences: Open Workspace Settings (JSON)을 고르고 Enter를 누릅니다. 명령 이름 전체를 쓸 필요는 없고 일부만 입력해도 찾아 줍니다. 명령 팔레트를 닫을 때는 Esc를 누릅니다.

      에디터에 .vscode/settings.json이 열립니다. 이 폴더에 미리 들어 있는 워크스페이스 설정이며, 아래 내용과 같아야 합니다. 이 파일은 // 주석을 쓸 수 있는 JSON(JSONC) 형식입니다.

      // 워크스페이스 설정입니다. 이 폴더(D:\study\rust)를 열었을 때만 적용되고, 내 PC 전체 설정(사용자 설정)보다 우선합니다.
// 설정 화면(Ctrl+,)의 Workspace 탭에서 값을 바꾸면 이 파일에 그대로 기록됩니다.
{
  // 새로 만드는 파일의 줄바꿈을 Windows 기본(CRLF)이 아닌 LF로 통일합니다(코스 제공 파일과 같은 형식).
  "files.eol": "\n",

  // 코드 줄 옆에 흐리게 보이는 추론 정보(인레이 힌트: 변수 타입, 매개변수 이름 등)의 표시 방식입니다.
  // on, off, onUnlessPressed, offUnlessPressed 중에서 고릅니다. off로 바꿔 보면 차이를 알 수 있습니다.
  "editor.inlayHints.enabled": "on",

  // Rust 파일(.rs)에는 중단점을 걸 수 있도록 기본으로 꺼져 있는 이 옵션을 켭니다(VS Code Rust 공식 문서 안내).
  "debug.allowBreakpointsEverywhere": true,

  // Rust 파일(.rs)에만 적용되는 설정 묶음입니다.
  "[rust]": {
    // 저장(Ctrl+S)할 때마다 rustfmt 표준 형식으로 자동 정렬합니다.
    "editor.formatOnSave": true,
    // 서식 정리를 rust-analyzer 확장(내부에서 rustfmt 실행)에 맡깁니다.
    "editor.defaultFormatter": "rust-lang.rust-analyzer"
  },

  // rust-analyzer가 읽을 Cargo 프로젝트를 lab 하나로 고정합니다.
  // 지정하지 않으면 폴더 안의 Cargo.toml을 전부 찾아 읽습니다. 이 폴더에는 클론한 axum 등이 있어 매우 느려집니다.
  "rust-analyzer.linkedProjects": ["lab/Cargo.toml"],

  // 클론한 자료 폴더는 rust-analyzer가 분석하지 않도록 제외합니다(경로는 이 폴더 기준, 와일드카드 불가).
  "rust-analyzer.files.exclude": ["axum", "rustlings", "the-rust-book", "rust-by-example"],

  // 저장할 때 실행하는 점검 명령을 기본값 check 대신 clippy(더 엄격한 린터)로 바꿉니다.
  "rust-analyzer.check.command": "clippy",

  // 디버그 버튼(Debug)이 사용할 디버거 확장입니다. Windows(MSVC 도구 체인)에서는 Microsoft C/C++ 확장을 씁니다.
  "rust-analyzer.debug.engine": "ms-vscode.cpptools",

  // 파일 변경 감시에서 빌드 산출물과 클론한 자료 폴더를 뺍니다. 감시 대상이 많으면 VS Code가 CPU를 많이 씁니다.
  "files.watcherExclude": {
    "**/target/**": true,
    "axum/**": true,
    "rustlings/**": true,
    "the-rust-book/**": true,
    "rust-by-example/**": true
  },

  // 전체 검색(Ctrl+Shift+F)에서 빌드 산출물 폴더(target)를 뺍니다.
  "search.exclude": {
    "**/target": true
  }
}

      이 코스의 설정 파일에서 눈여겨볼 곳: "[rust]" 블록은 .rs 파일에만 적용되는 설정 묶음이고, rust-analyzer.로 시작하는 키는 rust-analyzer 확장 전용 설정입니다. 각 줄 위의 // 주석이 무엇을 하는 설정인지 설명합니다.

    5. 빠른 열기로 파일 열기 (열린 폴더 필요)

      Ctrl+P를 누르고 launch를 입력합니다. 파일 이름 일부만 쳐도 됩니다. 목록 맨 위에 launch.json가 나타나면 Enter를 누릅니다. 입력창 맨 앞에 >를 붙이면 명령 팔레트와 같은 모드로 바뀝니다.

      이어서 Ctrl+G를 누르고 7를 입력한 뒤 Enter를 누르면 그 줄("version"이 적힌 줄)로 커서가 이동합니다. 이 Ctrl+G는 "줄로 이동(Go to Line)"입니다. 열린 탭은 Ctrl+W로 닫습니다.

    6. 사이드바·패널·터미널 켜고 끄기 (열린 폴더 필요)

      Ctrl+B를 누르면 사이드바가 사라지고 다시 누르면 나타납니다. Ctrl+J는 패널, Ctrl+`(Ctrl 키와 키보드 왼쪽 위의 백틱 키)는 통합 터미널을 열고 닫습니다. 터미널을 새로 하나 더 열 때는 Ctrl+Shift+`입니다. 백틱 키가 없는 키보드이면 명령 팔레트에서 Create New Terminal을 실행하거나 메뉴 Terminal > New Terminal을 씁니다.

      터미널은 열어 둔 폴더에서 시작합니다. 터미널에 pwd를 입력해 확인합니다. 셸 종류에 따라 출력 모양이 다릅니다.

      pwd
      Path

D:\study\rust
      pwd
      /d/study/rust

      PowerShell은 Windows 경로(D:\...)로, bash(MSYS2)는 슬래시 경로(/d/...)로 보여 줍니다. 둘 다 같은 폴더입니다.

    7. 터미널 프로필 고르기: PowerShell과 bash (6단계에서 연 터미널)

      터미널 오른쪽 위의 + 버튼 옆 아래쪽 화살표를 누르면 새 터미널에 쓸 셸 목록이 나타납니다. 이 목록의 항목이 "터미널 프로필(terminal profile)"입니다. 목록 아래쪽의 Select Default Profile을 고르면 새 터미널의 기본 셸을 정할 수 있습니다. 공식 문서는 Windows의 기본값이 PowerShell이라고 설명합니다.

      이 PC의 기본 터미널이 MSYS2 bash(예: 프로필 이름 MSYS2 UCRT64)로 설정되어 있다면 터미널 제목 표시줄에서 이름을 확인할 수 있습니다. 여기서 한 가지를 미리 알아 둡니다.

      MSYS2 bash에서는 cargo, rustc 명령을 못 찾을 수 있습니다MSYS2 bash는 시작할 때 Windows의 PATH를 이어받지 않는 것이 기본 동작(MSYS2_PATH_TYPE 미설정)입니다. 이 PC에서 사용자 프로필과 같은 조건으로 확인했을 때 cargo, rustc 명령이 모두 "명령을 찾을 수 없음"으로 나왔습니다. 해결 방법은 레슨 01에서 다룹니다. 간단히는 새 터미널을 PowerShell 프로필로 열면 됩니다.
    8. 설정 화면에서 값 바꾸고 settings.json 확인하기 (4단계에서 연 폴더)

      Ctrl+,를 눌러 설정(Settings) 화면을 엽니다. 위쪽 검색창에 minimap을 입력하면 Editor › Minimap: Enabled 설정이 보입니다. 검색창 아래에 User와 Workspace 탭이 있습니다. User는 내 PC 전체에 적용되는 사용자 설정, Workspace는 이 폴더에만 적용되는 워크스페이스 설정입니다.

      1. Workspace 탭을 누르고 Editor › Minimap: Enabled 체크를 끕니다. 열려 있는 파일의 오른쪽 가장자리에 있던 미니맵(코드 전체를 축소해 보여 주는 띠)이 사라집니다. 설정 왼쪽에 값이 바뀌었음을 나타내는 색 막대가 생깁니다.
      2. User 탭으로 돌아가 같은 설정을 보면 체크가 그대로 켜져 있습니다. 바꾼 값은 이 폴더에만 적용되었기 때문입니다.
      3. Ctrl+Shift+P에서 Open Workspace Settings (JSON)을 실행해 .vscode/settings.json을 열면 "editor.minimap.enabled": false 줄이 추가된 것을 볼 수 있습니다. 설정 화면의 조작이 곧 이 파일의 내용입니다.
      4. 원래대로 되돌립니다. 설정 화면에서 해당 설정 옆의 톱니바퀴 아이콘을 누르고 Reset Setting을 고르면 값이 기본값으로 돌아가고 JSON의 그 줄도 사라집니다.

      같은 설정이 여러 곳에 있으면 더 구체적인 쪽이 이깁니다. 공식 문서의 순서는 기본값 < 사용자 설정 < 워크스페이스 설정이며, 뒤쪽이 앞쪽을 덮어씁니다. 사용자 설정 파일은 Windows에서 %APPDATA%\Code\User\settings.json, 워크스페이스 설정 파일은 열어 둔 폴더의 .vscode/settings.json입니다.

      설정을 찾는 요령검색창에 @modified를 입력하면 기본값에서 바꾼 설정만 모아 보입니다. 설정 화면 대신 JSON 파일이 바로 열리게 하려면 workbench.settings.editor를 json으로 바꿉니다. 설정 JSON을 직접 고쳐 보는 연습은 레슨 12에서 합니다.
      JSON을 직접 고칠 때쉼표 하나만 빠져도 설정을 저장하지 못하고 Unable to write into user settings. Please open user settings to correct errors/warnings in it and try again. 같은 메시지가 나옵니다. 아래 "자주 나는 오류"를 참고하세요.
    9. 단축키 편집기 둘러보기 (바꾸지 않고 보기만)

      Ctrl+K Ctrl+S(Ctrl+K를 누른 뒤 이어서 Ctrl+S)를 누르면 키보드 단축키(Keyboard Shortcuts) 편집기가 열립니다. 검색창에 Toggle Panel을 입력하면 해당 명령과 단축키 Ctrl+J가 보입니다. 검색창에는 명령 이름뿐 아니라 단축키(예: Ctrl+J)도 입력할 수 있어서, 그 키가 어떤 명령에 묶여 있는지 거꾸로 찾아볼 수도 있습니다. 목록의 항목을 오른쪽 클릭해 Show Same Keybindings를 고르면 같은 키를 쓰는 다른 명령(충돌)을 볼 수 있습니다. 여기서는 아무 것도 바꾸지 말고 Esc로 닫습니다.

      단축키를 직접 고치는 방법(keybindings.json)은 레슨 12에서 다룹니다. 표시되는 단축키는 현재 키보드 배열 기준이라는 점도 기억해 두세요. 이 코스의 모든 단축키는 치트시트에 모아 두었습니다.

    10. 확대·축소, 자동 저장, 표시 언어 알아 두기

      확대·축소: Ctrl+=으로 창 전체(글자와 화면 요소)를 키우고, Ctrl+-로 줄입니다. 원래 크기로 돌리는 단축키는 Ctrl+Numpad0(숫자 키패드의 0)이며, 키패드가 없으면 명령 팔레트에서 Reset Zoom을 실행합니다. 값은 window.zoomLevel 설정에 기록됩니다.

      자동 저장: 메뉴 File의 Auto Save 항목은 files.autoSave 설정을 켜고 끕니다. 기본값은 꺼짐(off)입니다. 저장하지 않은 파일은 탭에 점 표시가 붙습니다. 중요한 점: afterDelay로 자동 저장을 켜면 "저장할 때 서식 정리(editor.formatOnSave)"가 직접 저장(Ctrl+S)했을 때만 동작합니다(VS Code 설정 설명 문구). 이 코스는 저장할 때 코드가 정렬되는 모습을 보여 주므로 자동 저장은 꺼 둔 채 진행하는 것을 권합니다.

      표시 언어(선택): VS Code 메뉴를 한국어로 보려면 명령 팔레트에서 Configure Display Language를 실행하거나, 확장 보기에서 MS-CEINTL.vscode-language-pack-ko(Korean Language Pack)를 설치합니다. 설치 후 다시 시작하라는 안내가 나옵니다. 이 코스의 설명은 영어 메뉴 이름을 기준으로 쓰여 있으므로, 한국어로 바꾸면 이름이 다르게 보일 수 있어 영어 상태로 따라 하는 편이 쉽습니다. 같은 명령으로 언제든 되돌릴 수 있습니다.

    1. 파일 열기와 줄 이동

      Ctrl+P를 누르고 tasks.json를 입력한 뒤 Enter를 누릅니다. 이어서 Ctrl+G를 누르고 5를 입력해 Enter를 누릅니다. 커서가 "version"이 있는 줄로 이동합니다.

    2. 사이드바 숨겼다가 되돌리기

      Ctrl+B를 두 번 누릅니다. 사이드바가 사라졌다가 다시 나타납니다.

    3. 터미널에서 위치 확인하기

      Ctrl+`로 터미널을 열고 pwd를 입력해 Enter를 누릅니다. 코스 폴더 경로가 나옵니다. 확인했으면 Ctrl+J로 패널을 닫습니다.

    4. 명령 팔레트로 설정 파일 열기

      Ctrl+Shift+P를 누르고 workspace settings json을 입력해 Open Workspace Settings (JSON)을 실행합니다.

    5. 설정 검색하기

      Ctrl+,를 누르고 formatOnSave를 입력합니다. Editor: Format On Save 설정이 나타납니다. Esc로 닫습니다.

    6. 탭 전환하고 정리하기

      Ctrl+Tab를 눌러 방금 보던 파일로 돌아가 보고, Ctrl+W를 여러 번 눌러 열린 탭을 모두 닫습니다.

    7. 탐색기와 확장 보기로 이동하기

      Ctrl+Shift+E로 탐색기를, Ctrl+Shift+X로 확장 보기를 엽니다. 마지막으로 Ctrl+Shift+E를 눌러 탐색기로 돌아옵니다.

    8. 단축키 편집기 열고 닫기

      Ctrl+K Ctrl+S로 단축키 편집기를 열고 검색창에 Quick Open을 입력해 Ctrl+P가 보이는지 확인한 뒤 Esc로 닫습니다.

    막힐 때 보는 힌트

    입력창(빠른 열기, 명령 팔레트)이 열려 있을 때는 Esc가 입력창을 닫습니다. 입력창에서 동작하지 않는 단축키가 있으면 일단 Esc로 닫고 다시 시도하세요. 터미널에 포커스가 있을 때는 일부 단축키가 터미널 쪽으로 전달될 수 있으니, 단축키가 안 먹으면 에디터를 한 번 클릭하지 말고 Ctrl+J로 패널을 닫아 포커스를 에디터로 옮겨 보세요.

    확인 퀴즈

    답을 먼저 떠올린 뒤 펼쳐 보세요.

    퀴즈 1. 폴더 열기와 파일 열기는 무엇이 다른가요?

    폴더 열기는 폴더 전체를 작업 공간으로 엽니다. 탐색기에 구조가 보이고, 그 폴더의 .vscode 설정이 적용되며, 터미널이 그 폴더에서 시작합니다. 파일 열기는 파일 하나만 엽니다.

    퀴즈 2. 명령 팔레트와 빠른 열기의 차이는?

    명령 팔레트(Ctrl+Shift+P)는 기능(명령)을 이름으로 찾고, 빠른 열기(Ctrl+P)는 파일을 이름으로 찾습니다. 빠른 열기 입력창 맨 앞에 >를 붙이면 명령 팔레트가 됩니다.

    퀴즈 3. 이 폴더에서만 적용되는 설정은 어디에 저장되나요?

    열어 둔 폴더의 .vscode/settings.json에 저장됩니다(워크스페이스 설정). 내 PC 전체에 적용되는 사용자 설정은 Windows에서 %APPDATA%\Code\User\settings.json에 있고, 같은 설정이 둘 다 있으면 워크스페이스 설정이 이깁니다.

    FIX자주 나는 오류

    증상: 제한 모드(Restricted Mode)라서 터미널·디버그가 막힌다

    폴더를 신뢰하지 않으면 터미널을 열 때 신뢰 확인이 다시 나오고, 취소하면 터미널이 열리지 않습니다. VS Code는 이 상태를 알릴 때 다음과 같은 문구를 사용합니다.

    Restricted Mode: Some features are disabled because this folder is not trusted.

    원인과 해결: 이 폴더를 아직 신뢰하지 않은 상태입니다. 배너나 배지의 Manage에서 신뢰하거나, 명령 팔레트에서 Workspaces: Manage Workspace Trust를 실행해 신뢰합니다. 신뢰하면 이 폴더의 터미널, 작업, 디버깅, 워크스페이스 설정이 모두 정상 동작합니다.

    증상: 설정을 바꾸려는데 저장되지 않는다

    Unable to write into user settings. Please open user settings to correct errors/warnings in it and try again.

    원인과 해결: settings.json의 JSON 문법이 깨져 있습니다(쉼표 누락 등이 가장 흔합니다). 파일을 열면 잘못된 곳에 빨간 물결선이 표시됩니다. 명령 팔레트에서 Preferences: Open User Settings (JSON) 또는 Preferences: Open Workspace Settings (JSON)으로 파일을 열어 빨간 물결선을 고친 뒤 저장하세요.

    증상: bash 터미널에서 cargo, rustc 명령을 찾지 못한다

    bash: cargo: 명령을 찾을 수 없음
bash: rustc: 명령을 찾을 수 없음

    원인과 해결: 기본 터미널이 MSYS2 bash이면 Windows의 PATH가 이어지지 않아 이런 메시지가 나옵니다(이 PC에서 같은 조건으로 확인한 실제 출력입니다). 터미널 프로필을 PowerShell로 바꿔 새 터미널을 열면 해결됩니다. bash를 계속 쓰려면 MSYS2 프로필의 env 안에 "MSYS2_PATH_TYPE": "inherit" 한 줄을 추가하면 Windows PATH를 이어받습니다(이 설정을 넣었을 때 같은 명령이 찾아지는 것을 확인했습니다). 자세한 순서는 레슨 01에서 다룹니다.

    증상: 단축키가 먹지 않는다

    원인과 해결: 다른 프로그램이 같은 키를 가로채는 경우가 많습니다. 공식 문서는 그래픽 카드 드라이버(예: NVIDIA)가 Ctrl+Alt+↑·Ctrl+Alt+↓ 같은 기본 단축키를 덮어쓸 수 있다고 안내합니다. 단축키 편집기(Ctrl+K Ctrl+S)에서 그 키를 검색해 어떤 명령이 묶여 있는지 확인하고, 명령 팔레트의 Developer: Toggle Keyboard Shortcuts Troubleshooting을 실행한 뒤 키를 눌러 보면 VS Code가 어떤 키로 인식하는지 출력 패널에 기록됩니다.

    증상: 탐색기에 lab 폴더가 보이지 않는다

    원인과 해결: 코스 폴더가 아닌 다른 폴더(예: 상위 폴더 D:\study나 lessons 폴더)를 열었을 가능성이 큽니다. 메뉴 File > Open Folder...(Ctrl+K Ctrl+O)로 D:\study\rust를 다시 엽니다. 최근에 연 폴더는 File > Open Recent에서 고를 수 있습니다.

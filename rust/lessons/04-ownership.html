    LESSON 04 · 소유권

    소유권·빌림·슬라이스

    Rust에서 가장 낯선 개념인 소유권을 JVM 참조와 대비해 이해합니다. 컴파일 오류를 일부러 만들어 보고, 오류 메시지가 소유권 규칙의 어느 줄을 어겼다고 말하는지 읽을 수 있게 됩니다.

    • 소요 약 150분
    • 난이도 ★★★★☆
    • 선행 레슨 03
    • 실습 폴더 lab/lesson04

    GOAL학습 목표

    • 소유권 규칙 세 가지(값마다 소유자 하나, 소유자는 한 번에 하나, 소유자가 사라지면 값도 정리)를 JVM 참조와 비교해 말로 설명할 수 있다.
    • let s2 = s1;이 이동(move)이라는 것을 실행해서 확인하고, borrow of moved value 오류를 읽어 clone이나 참조로 고칠 수 있다.
    • clone과 Copy의 차이를 설명하고, 어떤 타입이 Copy인지 구분할 수 있다.
    • &(읽기 참조)와 &mut(쓰기 참조)의 규칙을 어기는 코드를 일부러 만들어 컴파일러 메시지(E0499, E0502, E0596)를 읽고 고칠 수 있다.
    • 슬라이스(&str, &[T])로 first_word를 구현하고 테스트할 수 있다.
    • VS Code의 문제 패널, 다음 문제 이동, Quick Fix, 호버로 소유권 오류를 읽는 흐름을 손으로 해 볼 수 있다.

    핵심 개념 한국어 요약

    소유권(ownership) 규칙은 세 줄입니다. 값마다 소유자(owner)인 변수가 있고, 소유자는 한 번에 하나뿐이며, 소유자가 범위(scope)를 벗어나면 값이 정리(drop)됩니다. JVM에서는 val b = a가 같은 객체를 가리키는 참조를 하나 더 만들 뿐이고, 가비지 컬렉터(GC)가 마지막 참조가 사라진 뒤 언젠가 메모리를 거둡니다. Rust에는 GC가 없습니다. 대신 컴파일러가 코드 구조만 보고 "이 값은 이 줄에서 정리된다"를 정해 둡니다. 같은 값이 두 곳에서 정리되는 사고(이중 해제)를 막으려면 소유자가 하나여야 하기 때문에, 대입하면 소유권이 이동(move)하고 원래 변수는 더 이상 쓸 수 없습니다.

    String 변수는 글자 데이터가 있는 힙 메모리를 가리키는 작은 머리(포인터, 길이, 용량 세 값)입니다. let s2 = s1;은 이 머리만 복사하고 s1을 무효로 표시하며, 힙의 글자는 복사하지 않아서 빠릅니다. 실습에서 이 머리의 크기가 24바이트인 것을 직접 확인합니다. 글자까지 통째로 복사하려면 s1.clone()이라고 명시적으로 비용을 치릅니다. 정수, bool, char, 소수처럼 스택에 다 들어가는 작은 값은 Copy 타입이라서 대입해도 이동이 아니라 비트 복사이고 원본도 계속 씁니다. 함수에 값을 넘기는 것도 대입과 같아서, String을 인자로 넘기면 소유권이 함수로 이동합니다.

    매번 소유권을 넘기고 돌려받으면 불편하니 참조(reference)로 빌립니다(borrow). &s는 읽기 전용 참조, &mut s는 읽고 쓸 수 있는 참조입니다. 규칙은 하나로 외울 수 있습니다. 같은 시점에 읽기 참조 여러 개이거나, 쓰기 참조 딱 하나이며 둘이 섞일 수 없습니다. 읽는 사람이 있는 동안 아무도 바꾸지 못하고, 바꾸는 사람이 있는 동안 아무도 읽지 못하게 해서 데이터 경쟁과 반복 중 수정 같은 버그를 컴파일 시점에 없애는 규칙입니다. 참조의 빌림은 참조를 마지막으로 쓰는 줄에서 끝납니다. 참조는 가리키는 값보다 오래 살 수 없어서, 함수가 지역 변수의 참조를 반환하는 댕글링 참조(dangling reference)도 컴파일러가 막습니다.

    슬라이스(slice)는 컬렉션의 일부를 가리키는 참조입니다. &str은 문자열 일부(또는 전체)를 가리키는 슬라이스이고, 포인터와 길이 두 값이라 16바이트입니다. 슬라이스도 빌림이므로 슬라이스가 살아 있는 동안 원본을 수정할 수 없습니다. 함수 인자로는 &String보다 &str이 더 널리 쓰이는 이유가 여기에 있습니다.

    1. 이동·복제·Copy 입력하기

      (앞 단계 없음) 탐색기(Ctrl+Shift+E)에서 lab/lesson04/src/bin에 my_move_basics.rs를 만들고 아래 코드를 입력한 뒤 Ctrl+S로 저장하고 실행합니다.

      fn takes_ownership(s: String) {
    println!("함수 안: {s}");
}

fn makes_copy(n: i32) {
    println!("함수 안: {n}");
}

fn gives_back(s: String) -> String {
    s
}

fn main() {
    let s1 = String::from("hello");
    let s2 = s1;
    println!("s2 = {s2}");

    let s3 = s2.clone();
    println!("s2 = {s2}, s3 = {s3}");

    let n = 5;
    let m = n;
    println!("n = {n}, m = {m}");

    makes_copy(n);
    println!("makes_copy 뒤에도 n = {n}");

    takes_ownership(s3);

    let s4 = gives_back(s2);
    println!("돌려받은 s4 = {s4}");

    println!(
        "String 값 하나의 크기: {}바이트",
        std::mem::size_of::<String>()
    );
}

      줄 순서대로 읽습니다. let s2 = s1; 뒤에는 s1을 쓰지 않고 s2만 씁니다. s2.clone()은 글자까지 복사해서 두 변수 모두 쓸 수 있습니다. n과 m은 정수라 Copy이므로 둘 다 살아 있고, makes_copy(n) 뒤에도 n을 씁니다. takes_ownership(s3) 뒤에는 s3를 쓸 수 없습니다. 마지막의 gives_back은 소유권을 받았다가 그대로 돌려주는 함수입니다. 끝 줄은 String 변수 하나의 크기가 24바이트라는 것을 보여 줍니다(포인터·길이·용량).

      4. Ctrl+.을 누르면 Quick Fix 목록이 열립니다. 목록에 clone을 붙이라는 제안이 있으면 적용해 보세요. 어떤 제안이 보이는지는 오류 종류와 rust-analyzer 버전에 따라 다르며, 제안이 없으면 메시지의 help: 줄(s1.clone())을 보고 직접 let s2 = s1.clone();으로 고칩니다.

    3. 빌림 입력하기

      (2단계의 scratch.rs는 두고) my_borrowing.rs를 만들어 입력하고 실행합니다. 빌림이 소유권을 옮기지 않기 때문에 length(&s) 뒤에도 s를 계속 쓸 수 있습니다.

      fn length(s: &str) -> usize {
    s.len()
}

fn add_world(s: &mut String) {
    s.push_str(", world");
}

fn main() {
    let mut s = String::from("hello");

    let len = length(&s);
    println!("'{s}'의 길이는 {len}");

    println!("바뀐 값: {s}");

    let r2 = &s;
    println!("읽기 참조 두 개: {r1} / {r2}");

    let r3 = &mut s;
    r3.push('!');
    println!("가변 참조: {r3}");
    println!("원래 변수: {s}");
}

      E0502는 "읽기 빌림이 있는데 쓰기 빌림을 했다"는 뜻입니다. 세 줄 표시가 한 이야기를 이룹니다. 읽기 빌림이 여기서 시작하고(3번 줄), 쓰기 빌림이 여기서 일어나며(4번 줄), 읽기 참조가 나중에 또 쓰입니다(5번 줄). 고치는 방법은 읽기 참조의 마지막 사용을 쓰기보다 앞으로 옮기는 것입니다. println!("{first}"); 줄을 log.push_str(…) 줄 위로 옮기고 저장하면 통과합니다. 줄 이동은 레슨 03에서 익힌 Alt+↑로 합니다.

    7. 정리(drop)와 구현으로 이동 (Ctrl+F12)

      (6단계와 별개) JVM은 객체를 언제 정리할지 GC가 정하지만, Rust는 소유자가 범위를 벗어나는 줄에서 정리합니다. 이 시점을 눈으로 보기 위해 Drop trait을 구현한 예제를 실행합니다. trait과 impl 문법은 레슨 05, 07에서 배우니 지금은 "정리될 때 drop 함수가 자동으로 불린다"로만 이해합니다. 이미 들어 있는 drop_order.rs를 열어 읽고 실행합니다.

      struct Noisy {
    name: String,
}

impl Noisy {
    fn new(name: &str) -> Noisy {
        println!("{name} 만들어짐");
        Noisy {
            name: name.to_string(),
        }
    }
}

impl Drop for Noisy {
    fn drop(&mut self) {
        println!("{} 정리됨", self.name);
    }
}

fn consume(item: Noisy) {
    println!("consume 안: {}", item.name);
}

fn main() {
    let a = Noisy::new("a");
    {
        let _b = Noisy::new("b");
        println!("안쪽 블록 끝");
    }
    consume(a);

    let c = Noisy::new("c");
    drop(c);

    println!("main 끝");
    let _d = Noisy::new("d");
}

    힌트 보기

    text.find('.')는 마침표의 바이트 위치를 Some(위치)로, 없으면 None으로 돌려줍니다(Option은 레슨 05). 위치를 얻으면 &text[..=위치]로 마침표까지 자릅니다. 마침표는 1바이트 글자이므로 한국어가 앞에 있어도 경계가 맞습니다.

    정답 예시 보기 
    fn first_sentence(text: &str) -> &str {
    match text.find('.') {
        Some(end) => &text[..=end],
        None => text,
    }
}

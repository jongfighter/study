    핵심 개념 한국어 요약

    제네릭(generics)은 타입을 나중에 정하겠다는 표시입니다. 함수 이름 뒤 <T>가 "여기 들어올 타입을 T라고 부르겠다"는 선언입니다. JVM의 제네릭은 컴파일 후 타입 정보가 지워지는 타입 소거(type erasure) 방식이지만, Rust는 쓰인 타입마다 코드를 따로 만들어 내는 단형성화(monomorphization)를 합니다. 그래서 제네릭을 써도 실행 중 비용이 늘지 않습니다.

    trait은 "이 타입은 이런 일을 할 수 있다"는 약속입니다. Kotlin의 interface와 닮았지만 두 가지가 다릅니다. 첫째, 구현을 타입 정의 안이 아니라 impl Trait for 타입이라는 별도 블록에 씁니다. 둘째, 상속이 없고 오직 "약속의 집합"만 있습니다. 메서드에 본문을 적어 두면 기본 구현(default method)이 되어, 구현하는 쪽이 생략할 수 있습니다.

    trait bound는 제네릭에 능력을 요구하는 문법입니다. fn largest<T: PartialOrd>는 "비교할 수 있는 타입만 받겠다"는 뜻이고, 이 조건이 없으면 함수 안에서 > 연산을 쓸 수 없습니다. 같은 뜻을 &impl Trait나 where 절로도 쓸 수 있습니다.

    trait 객체(trait object)는 Box<dyn Notifier>처럼 실행 중에 구현체가 정해지는 타입입니다. Kotlin에서 List<Notifier>를 쓰던 자리가 Rust에서는 Vec<Box<dyn Notifier>>입니다. 메서드 호출이 가상 함수 표(vtable)를 거치므로 동적 디스패치(dynamic dispatch)이고, 제네릭이나 impl Trait는 컴파일 때 호출 대상이 정해지는 정적 디스패치(static dispatch)입니다.

    라이프타임(lifetime)은 참조가 가리키는 값이 얼마나 오래 사는지를 컴파일러가 따져 보기 위한 이름표입니다. JVM에는 가비지 컬렉터가 있어 이런 개념이 없습니다. 'a는 값의 수명을 늘려 주는 것이 아니라 "이 참조들은 서로 이런 관계다"라고 적어 주는 설명서입니다. 참조 하나를 받아 참조 하나를 돌려주는 흔한 경우에는 컴파일러가 알아서 채워 주는 생략 규칙(elision)이 있어서 대부분 'a를 직접 쓸 일이 없습니다.

    2. 제네릭 함수와 제네릭 구조체 (mine.rs, 1단계 의존)

      mine.rs에 아래 코드를 입력합니다. largest는 어떤 타입의 슬라이스든 받아 가장 큰 원소의 참조를 돌려주고, Page<T>는 목록 응답을 담는 그릇입니다.

      use std::fmt::{self, Display};

// ── 1. 제네릭: 타입을 나중에 정한다 ─────────────────────────────

fn largest<T: PartialOrd>(items: &[T]) -> Option<&T> {
    let mut iter = items.iter();
    let mut max = iter.next()?;
    for item in iter {
        if item > max {
            max = item;
        }
    }
    Some(max)
}

#[derive(Debug)]
struct Page<T> {
    items: Vec<T>,
    total: usize,
}

impl<T> Page<T> {
    fn new(items: Vec<T>, total: usize) -> Self {
        Page { items, total }
    }

    fn has_more(&self) -> bool {
        self.items.len() < self.total
    }
}

impl<T: Display> Page<T> {
    fn describe(&self) -> String {
        let mut parts = Vec::new();
        for item in &self.items {
            parts.push(item.to_string());
        }
        format!("[{}] 총 {}건", parts.join(", "), self.total)
    }
}

fn demo_generics() {
    println!("{:?}", largest(&[3, 9, 4]));
    println!("{:?}", largest(&[1.5, 0.2]));
    println!("{:?}", largest(&["rust", "kotlin", "python"]));
    let empty: [i32; 0] = [];
    println!("{:?}", largest(&empty));

    let page = Page::new(vec![10, 20, 30], 5);
    println!("{} / 더 있나? {}", page.describe(), page.has_more());
}

      // ── 2. trait: 같은 행동을 약속한다 ──────────────────────────────

trait Notifier {
    fn name(&self) -> String;
    fn send(&self, to: &str, message: &str) -> String;

    fn broadcast(&self, recipients: &[&str], message: &str) -> Vec<String> {
        let mut results = Vec::new();
        for to in recipients {
            results.push(self.send(to, message));
        }
        results
    }
}

struct EmailNotifier {
    domain: String,
}

struct SlackNotifier {
    channel: String,
}

impl Notifier for EmailNotifier {
    fn name(&self) -> String {
        String::from("email")
    }

    fn send(&self, to: &str, message: &str) -> String {
        format!("[email] {to}@{} <- {message}", self.domain)
    }
}

impl Notifier for SlackNotifier {
    fn name(&self) -> String {
        String::from("slack")
    }

    fn send(&self, to: &str, message: &str) -> String {
        format!("[slack #{}] @{to} <- {message}", self.channel)
    }
}

fn demo_notifiers() {
    let email = EmailNotifier {
        domain: String::from("example.com"),
    };
    let slack = SlackNotifier {
        channel: String::from("dev"),
    };

    println!("{}", email.send("alice", "배포 완료"));
    for line in slack.broadcast(&["alice", "bob"], "점검 시작") {
        println!("{line}");
    }
}

    4. trait bound로 쓰기, Display 구현 (mine.rs, 3단계 의존)

      3단계 코드 아래에 이어서 입력합니다. Priority는 #[derive(PartialOrd, ...)]로 비교 능력을 자동으로 얻고, Display는 직접 impl합니다. 입력한 뒤 describe_largest 위에 마우스를 올리거나 커서를 두고 Ctrl+K Ctrl+I를 눌러 시그니처와 trait bound가 어떻게 표시되는지 확인해 보세요.

      // ── 3. trait bound: 제네릭에 "할 수 있는 일"을 요구한다 ───────────

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord)]
enum Priority {
    Low,
    Normal,
    High,
}

impl Display for Priority {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        let label = match self {
            Priority::Low => "낮음",
            Priority::Normal => "보통",
            Priority::High => "높음",
        };
        write!(f, "{label}")
    }
}

fn notify_one<N: Notifier>(notifier: &N, to: &str, message: &str) -> String {
    notifier.send(to, message)
}

fn announce(notifier: &impl Notifier, message: &str) -> Vec<String> {
    notifier.broadcast(&["alice", "bob"], message)
}

fn describe_largest<T>(items: &[T]) -> String
where
    T: PartialOrd + Display,
{
    match largest(items) {
        Some(max) => format!("가장 큰 값: {max}"),
        None => String::from("비어 있음"),
    }
}

fn demo_bounds() {
    let email = EmailNotifier {
        domain: String::from("example.com"),
    };
    let slack = SlackNotifier {
        channel: String::from("dev"),
    };

    println!("{}", notify_one(&email, "carol", "회의 시작"));
    for line in announce(&slack, "점검 종료") {
        println!("{line}");
    }

    let priorities = [Priority::Low, Priority::High, Priority::Normal];
    println!("{}", describe_largest(&priorities));
    println!("{}", describe_largest(&[2.5, 8.0, 1.0]));
}

    익숙함이 만드는 함정 ① — "인터페이스 타입이 곧 기본값"이 아닙니다Kotlin에서는 Notifier 타입을 쓰면 늘 동적 디스패치입니다. Rust에서는 제네릭이나 impl Trait가 기본 선택이고, 서로 다른 구현체를 한 컬렉션에 섞을 때만 Box<dyn Trait>를 씁니다. dyn을 습관처럼 쓰면 Kotlin과 비슷해 편하지만, 반환 타입이 Self인 메서드 같은 제약(E0038)에 걸립니다.
    익숙함이 만드는 함정 ② — 'a는 수명을 늘려 주지 않습니다라이프타임 표기는 이미 정해진 관계를 컴파일러에게 설명하는 것일 뿐, 값을 더 오래 살게 하지 못합니다. 오류가 나면 표기를 만지작거리기 전에 "그 값이 어디서 만들어져 어디서 버려지는가"를 먼저 그려 보세요. 대부분은 값을 복사(.to_string(), .clone())하거나 선언 위치를 옮기면 해결됩니다.
    익숙함이 만드는 함정 ③ — 남의 타입에 마음대로 구현할 수 없습니다Kotlin의 확장 함수는 어느 타입에나 붙일 수 있습니다. Rust는 trait이나 타입 둘 중 하나가 내 크레이트 것이어야 impl할 수 있습니다(고아 규칙, orphan rule). 표준 라이브러리 타입에 표준 trait을 구현하려면 새 타입으로 감싸야 합니다. 실제 오류는 아래 "자주 나는 오류"에 있습니다.

        • 빈 프로필(Empty Profile)로 만들지 마세요. 공식 문서에 따르면 빈 프로필에는 설정·확장·스니펫이 하나도 없어서 rust-analyzer 같은 확장이 빠지고, 이 코스의 실험이 동작하지 않습니다.
        • 체크를 풀지 마세요. 공식 문서에 따르면 체크하지 않은 항목은 기본 프로필의 것을 그대로 쓰기 때문에, 그 항목을 이 프로필에서 고치면 기본 프로필이 바뀝니다.
      3. 확인합니다. 관리 아이콘에 프로필 이름의 앞 두 글자가 배지로 보이고, 아이콘에 마우스를 올리면 프로필 이름이 나옵니다. 공식 문서는 기본 프로필을 쓰는 중에는 프로필 이름이 표시되지 않는다고 설명하므로, 이름이 보이면 연습용 프로필을 쓰는 중입니다. 프로필을 만들거나 고르면 현재 폴더에 연결되어 다음에 이 폴더를 열 때도 그 프로필이 쓰이므로, 실험이 끝나면 반드시 아래 순서로 삭제합니다.
    2. 라이프타임 인레이 힌트를 켜고, 설정 파일에 기록되는 모습 확인하기 (연습용 프로필 안에서)

      (프로필 이름이 관리 아이콘에 보이는 상태에서) Ctrl+,로 설정 화면을 열고 lifetimeElisionHints를 검색합니다. 값을 always로 바꾼 뒤 완성본 lab/lesson07/src/main.rs의 fn first_line(&self) -> &str를 보면 '0 이름표가 나타납니다. 값이 skip_trivial이면 단순한 경우를 건너뛰고, 입력 참조가 둘 이상이라 헷갈리기 쉬운 곳만 보여 줍니다.

      이 값은 연습용 프로필의 설정 파일에 저장됩니다. 설정 화면 오른쪽 위의 설정 열기(JSON) 아이콘을 누르면 VS Code가 현재 프로필의 설정 파일을 엽니다(VS Code 소스의 명령 설명: 현재 사용자 프로필의 설정 JSON). 거기에 "rust-analyzer.inlayHints.lifetimeElisionHints.enable": "always" 한 줄이 생겼는지 확인하세요. 이 파일은 기본 프로필의 settings.json이 아닙니다. 이 코스의 완성본 .vscode/settings.json에는 이 항목이 들어 있지 않으므로(기본값 never) 직접 켜 보는 설정입니다. 반면 editor.inlayHints.enabled와 rust-analyzer.check.command는 완성본에 이미 들어 있습니다.

    3. 구현 개수를 알려 주는 CodeLens 껐다 켜기 (연습용 프로필 안에서)

      설정에서 lens.implementations를 검색해 Lens: Implementations: Enable(rust-analyzer.lens.implementations.enable) 체크를 해제합니다. trait Notifier 위의 구현 개수 링크가 사라집니다. 다시 체크하면 돌아옵니다. 기본값은 켜짐입니다.

      2. 확인합니다. 관리 아이콘의 두 글자 배지가 사라지고, 마우스를 올려도 프로필 이름이 나오지 않아야 합니다(기본 프로필).

    문제 1. 세 번째 알림 방식과 일괄 발송

    Notifier를 구현하는 SmsNotifier { country_code: String }을 만드세요. send는 [sms +82] dave <- 회의 10분 전 형식으로 돌려줍니다. 그리고 fn broadcast_all(notifiers: &[Box<dyn Notifier>], recipients: &[&str], message: &str) -> Vec<String>를 만들어, 모든 알림 방식으로 모든 수신자에게 보낸 결과를 한 목록으로 돌려주세요.

    완료 조건: 이메일과 SMS 두 구현체를 담은 목록에 ["dave", "erin"]을 넣었을 때 4줄이 이메일 두 줄, SMS 두 줄 순서로 출력된다.

    힌트 보기

    각 알림 방식의 broadcast(기본 구현)를 호출하고, 그 결과 Vec을 results.extend(...)로 이어 붙이세요. Ctrl+.의 Implement missing members가 impl 뼈대를 만들어 줍니다.

    정답 예시 보기 
    struct SmsNotifier {
    country_code: String,
}

impl Notifier for SmsNotifier {
    fn name(&self) -> String {
        String::from("sms")
    }

    fn send(&self, to: &str, message: &str) -> String {
        format!("[sms +{}] {to} <- {message}", self.country_code)
    }
}

fn broadcast_all(
    notifiers: &[Box<dyn Notifier>],
    recipients: &[&str],
    message: &str,
) -> Vec<String> {
    let mut results = Vec::new();
    for notifier in notifiers {
        results.extend(notifier.broadcast(recipients, message));
    }
    results
}

    기대 출력(전체 실행 출력의 일부)입니다.

    [email] dave@example.com <- 회의 10분 전
[email] erin@example.com <- 회의 10분 전
[sms +82] dave <- 회의 10분 전
[sms +82] erin <- 회의 10분 전

    문제 2. 제네릭 스택과 라이프타임

    제네릭 구조체 Stack<T>를 만드세요. new, push, pop, peek(&self) -> Option<&T>, len, is_empty가 필요합니다. 또 여러 줄 문자열에서 가장 긴 줄을 참조로 돌려주는 fn longest_line(text: &str) -> &str도 만드세요. 길이가 같으면 먼저 나온 줄을 돌려줍니다.

    완료 조건: 문자열 두 개를 push한 뒤 peek가 Some("둘째")를 보여 주고, pop을 세 번 하면 Some("둘째"), Some("첫째"), None이 차례로 나온다. longest_line("짧음\n조금 더 긴 줄\n중간")은 조금 더 긴 줄이다.

    힌트 보기

    Vec<T>를 필드로 감싸고 last(), pop(), push()를 그대로 이어 주면 됩니다. longest_line은 반환 참조가 입력 text에서만 온다는 사실이 시그니처에서 읽히므로 'a를 쓰지 않아도 됩니다. "VS Code 기능" 절의 연습용 프로필에서 라이프타임 힌트를 always로 켠 채 확인해 보세요.

    정답 예시 보기 
    #[derive(Debug)]
struct Stack<T> {
    items: Vec<T>,
}

impl<T> Stack<T> {
    fn new() -> Self {
        Stack { items: Vec::new() }
    }

    fn push(&mut self, item: T) {
        self.items.push(item);
    }

    fn pop(&mut self) -> Option<T> {
        self.items.pop()
    }

    fn peek(&self) -> Option<&T> {
        self.items.last()
    }

    fn len(&self) -> usize {
        self.items.len()
    }

    fn is_empty(&self) -> bool {
        self.items.is_empty()
    }
}

fn longest_line(text: &str) -> &str {
    let mut best = "";
    for line in text.lines() {
        if line.len() > best.len() {
            best = line;
        }
    }
    best
}

    기대 출력(전체 실행 출력의 일부)입니다.

    peek = Some("둘째"), len = 2
pop = Some("둘째")
pop = Some("첫째")
pop = None, 비었나? true
가장 긴 줄: 조금 더 긴 줄

    fn largest<T: PartialOrd>(items: &[T]) -> Option<&T> {
    let mut iter = items.iter();
    let mut max = iter.next()?;
    for item in iter {
        if item > max {
            max = item;
        }
    }
    Some(max)
}

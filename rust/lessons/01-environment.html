    핵심 개념 한국어 요약

    rustup은 Rust 도구 체인 관리자입니다. JDK를 설치하고 버전을 바꿔 주는 SDKMAN, Gradle 래퍼(wrapper)를 합쳐 놓은 도구라고 생각하면 됩니다. rustup이 설치하는 것은 컴파일러 rustc, 빌드·의존성·테스트를 한 곳에서 맡는 cargo, 코드 정렬기 rustfmt, 린터 clippy 같은 프로그램들이고, 모두 %USERPROFILE%\.cargo\bin 폴더에 들어갑니다. 이 폴더가 PATH에 있어야 터미널에서 cargo를 부를 수 있습니다.

    Rust에는 stable(안정), beta, nightly 채널이 있고 이 코스는 stable만 씁니다. Windows에서는 두 종류의 도구 체인이 있습니다. 기본인 x86_64-pc-windows-msvc는 최종 실행 파일을 만들 때 Microsoft의 링커(linker) link.exe가 필요하고, 이것은 Visual Studio Build Tools의 C++ 도구에 들어 있습니다. 책도 설치 중에 Visual Studio를 설치하라는 안내가 나오는 이유가 링커와 네이티브 라이브러리 때문이라고 설명합니다.

    rust-analyzer는 VS Code가 Rust 코드를 이해하게 해 주는 언어 서버(language server)입니다. 자동 완성, 정의로 이동, 오류 표시가 모두 여기서 나옵니다. 공식 매뉴얼에 따르면 서버 실행 파일은 확장 설치 폴더에 함께 들어 있으므로 따로 설치하지 않아도 됩니다. rust-analyzer는 cargo에게 프로젝트 구조를 물어서 코드를 분석하기 때문에, Cargo.toml이 어디 있는지 알아야 합니다. 그래서 어떤 폴더를 열었는지, 그리고 linkedProjects 설정이 중요합니다.

    2. PowerShell 터미널에서 버전 확인하기

      (1단계 이후) Ctrl+`로 통합 터미널을 엽니다. 터미널 패널 오른쪽 위의 + 옆 ∨ 화살표를 누르면 프로필 목록이 나옵니다. 프로필 이름을 고르면 그 셸로 새 터미널이 열립니다. 여기서 PowerShell(또는 PowerShell 7) 항목을 골라 새 터미널을 엽니다. 프로필이 보이지 않으면 Ctrl+Shift+P로 명령 팔레트를 열어 Terminal: Select Default Profile을 찾아봅니다. 키보드 배열 때문에 백틱 키가 다르게 보이면 명령 팔레트에서 View: Toggle Terminal을 실행해도 됩니다.

      터미널에 다음 두 줄을 한 줄씩 입력하고 Enter를 누릅니다.

      rustc --version
cargo --version
      rustc 1.99.1 (58cf8f9c3 2026-10-13)
cargo 1.99.1 (5f94df478 2026-08-27)

      두 줄 모두 버전이 나오면 컴파일러와 cargo가 PATH에 있다는 뜻입니다. 오류가 나면 "자주 나는 오류"의 첫 번째 항목을 보세요.

    3. MSYS2 bash 터미널에서도 같은 명령 실행하기

      (2단계의 터미널은 열어 둔 채로) 패널의 ∨ 목록에서 이번에는 기본 프로필인 MSYS2 bash(이름은 환경마다 다르며 예: MSYS2 UCRT64) 항목으로 새 터미널을 엽니다. 같은 명령을 입력합니다.

      cargo --version

      MSYS2 프로필에 MSYS2_PATH_TYPE 환경 변수를 따로 주지 않았다면(기본값) 다음처럼 실패하는 것이 정상입니다.

      bash: cargo: 명령을 찾을 수 없음

      원인은 MSYS2 로그인 셸이 Windows의 PATH를 그대로 물려받지 않고 필요한 시스템 폴더만 남기기 때문입니다. 아래 명령으로 PATH를 줄 바꿈해서 보면 .cargo\bin이 없다는 것을 직접 확인할 수 있습니다.

      echo "$PATH" | tr ':' '\n'
      /ucrt64/bin
/usr/local/bin
/usr/bin
/bin
/c/Windows/System32
/c/Windows
/c/Windows/System32/Wbem
/c/Windows/System32/WindowsPowerShell/v1.0/
/usr/bin/site_perl
/usr/bin/vendor_perl
/usr/bin/core_perl

      이번 터미널에서만 고치려면 아래 한 줄을 입력합니다. cygpath는 Windows 경로를 MSYS2 경로로 바꿔 주는 도구입니다.

      export PATH="$PATH:$(cygpath -u "$USERPROFILE")/.cargo/bin"
cargo --version
which cargo
      cargo 1.99.1 (5f94df478 2026-08-27)
/c/Users/<사용자>/.cargo/bin/cargo

      새 터미널을 열 때마다 자동으로 적용하려면 MSYS2 홈의 ~/.bashrc 끝에 같은 줄을 추가합니다. 이 파일은 VS Code 설정이 아니라 MSYS2 셸 설정이라서 다른 프로젝트에도 영향을 줍니다. 부담스럽다면 이 코스에서는 터미널 프로필로 PowerShell을 골라 쓰면 됩니다. 세 번째 방법은 사용자 설정의 해당 프로필에 "MSYS2_PATH_TYPE": "inherit" 환경 변수를 추가해 MSYS2가 Windows의 PATH를 그대로 이어받게 하는 것입니다(이 코스의 README.md가 소개하며, 적용 후 cargo가 찾아지는 것을 직접 확인했습니다). 다만 이것은 모든 프로젝트에 적용되는 사용자 설정 변경이라서 바꾸기 전에 어떤 영향이 있는지 이해한 뒤에만 쓰세요.

      echo 'export PATH="$PATH:$(cygpath -u "$USERPROFILE")/.cargo/bin"' >> ~/.bashrc

      새 터미널을 열어 cargo --version이 바로 되는지 확인합니다.

    4. rustup show로 도구 체인 읽기

      (PowerShell 또는 보정한 bash 터미널에서) 다음 명령을 실행합니다.

      rustup show
      Default host: x86_64-pc-windows-msvc
rustup home:  C:\Users\<사용자>\.rustup

installed toolchains
--------------------
stable-x86_64-pc-windows-msvc (active, default)

active toolchain
----------------
name: stable-x86_64-pc-windows-msvc
active because: it's the default toolchain
installed targets:
  x86_64-pc-windows-msvc

      읽는 법은 세 가지입니다. Default host가 x86_64-pc-windows-msvc이면 MSVC 도구 체인입니다. installed toolchains에 stable-…이 (active, default)로 있으면 지금 쓰는 컴파일러가 stable입니다. installed targets는 이 도구 체인이 만들 수 있는 실행 파일의 종류입니다. 설치된 부속 도구는 다음 명령으로 봅니다.

      rustup component list --installed
      cargo-x86_64-pc-windows-msvc
clippy-x86_64-pc-windows-msvc
rust-docs-x86_64-pc-windows-msvc
rust-src
rust-std-x86_64-pc-windows-msvc
rustc-x86_64-pc-windows-msvc
rustfmt-x86_64-pc-windows-msvc

      rustfmt와 clippy가 있으면 레슨 02에서 쓸 포맷터와 린터가 이미 준비된 것입니다.

    5. MSVC 빌드 도구가 있는지 확인하기

      (4단계 이후) Visual Studio 설치 위치를 찾아 주는 Microsoft의 vswhere 도구로 C++ 도구가 설치돼 있는지 확인합니다. PowerShell에서는 다음 명령을 입력합니다.

      & "${env:ProgramFiles(x86)}\Microsoft Visual Studio\Installer\vswhere.exe" -latest -products * -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath

      bash에서는 경로 표기와 별표 따옴표만 다릅니다.

      "/c/Program Files (x86)/Microsoft Visual Studio/Installer/vswhere.exe" -latest -products '*' -requires Microsoft.VisualStudio.Component.VC.Tools.x86.x64 -property installationPath
      C:\Program Files (x86)\Microsoft Visual Studio\18\BuildTools

      설치 경로가 한 줄 나오면 C++ 도구가 있다는 뜻입니다(폴더 이름의 숫자는 버전에 따라 다릅니다). 아무것도 안 나오면 Visual Studio Build Tools를 설치하면서 C++를 사용한 데스크톱 개발(Desktop development with C++) 워크로드를 선택해야 합니다(VS Code 공식 문서). Visual Studio 설치 프로그램의 작업은 관리자 권한을 요구하므로 UAC 승인 창이 뜰 수 있습니다(Microsoft Learn의 설치 명령줄 문서가 "Visual Studio Installer operations currently require administrator privileges"라고 안내합니다). 이 PC에는 이미 설치돼 있어 따로 할 필요가 없으니, 설치 창을 띄우기 전에 위 명령으로 먼저 확인하세요. 가장 확실한 증거는 9단계의 cargo check와 레슨 02의 cargo run 성공입니다. 참고로 MSYS2 bash에서는 which link가 MSYS2 자체의 link 프로그램을 가리키지만, PATH를 보정한 뒤에도 이 PC에서는 cargo 빌드가 성공했습니다(직접 확인).

    9. cargo check로 전체 연결 증명하기

      (PowerShell 또는 PATH를 보정한 bash 터미널에서) 새 터미널은 열어 둔 폴더(D:\study\rust)에서 시작합니다. 먼저 cargo가 Cargo.toml을 못 찾는 상황을 일부러 확인해 봅니다.

      cargo run
      error: could not find `Cargo.toml` in `D:\study\rust` or any parent directory

      cargo는 현재 폴더와 그 위쪽 폴더에서만 Cargo.toml을 찾습니다. 이 코스의 Rust 프로젝트는 lab 폴더 안에 있으므로 먼저 이동한 다음 검사합니다.

      cd lab
cargo check -p lesson02
          Checking lesson02 v0.1.0 (D:\study\rust\lab\lesson02)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.13s

      Checking과 Finished가 나오면 도구 체인, 링커 환경, 터미널 설정이 모두 정상입니다. 걸린 시간(in 0.15s)은 PC마다 다릅니다. cargo check는 실행 파일을 만들지 않고 오류만 검사하는 빠른 명령이며 자세한 의미는 레슨 02에서 다룹니다.

    폴더 열기와 워크스페이스, 작업 영역 신뢰

    VS Code에서 폴더를 연다는 것은 그 폴더 하나를 작업 영역(workspace)으로 쓴다는 뜻입니다. 이 코스는 D:\study\rust 폴더를 그대로 엽니다. 설정은 그 폴더의 .vscode 안에 저장되고, 사용자 전체 설정보다 우선합니다. 폴더 여러 개를 한 창에서 열고 싶을 때는 .code-workspace 파일을 쓰는 다중 루트 작업 영역이 있지만, 이 코스에서는 쓰지 않습니다.

    이 폴더 안에는 클론해 둔 외부 저장소(axum, rustlings, the-rust-book)가 있고 각각 Cargo.toml을 갖고 있습니다(GitHub에서 이 저장소를 새로 받았다면 이 폴더들은 없으니, 맨 위 README.md의 git clone 명령으로 받으세요. 받지 않아도 lab 실습은 진행됩니다). rust-analyzer가 이것들을 모두 분석하려 하면 느려지고 관계없는 오류가 섞입니다. 그래서 rust-analyzer.linkedProjects로 lab/Cargo.toml만 지정합니다. 공식 설정 설명은 이 값을 "프로젝트 자동 탐색을 끄고 명시한 프로젝트 목록만 쓴다"로 정의합니다.

    설정 체험하기

    1. 작업 영역 설정 읽기: rust-analyzer.linkedProjects

      Ctrl+,로 설정 화면을 열고, 검색창에 rust-analyzer.linkedProjects를 입력합니다. 검색 결과 아래의 작업 영역(Workspace) 탭을 누릅니다. 배열 형식 설정은 화면에서 직접 고치지 못하고 settings.json에서 편집(Edit in settings.json) 링크로 이동합니다. 링크를 눌러 .vscode/settings.json이 열리면 lab/Cargo.toml을 가리키는 항목이 이미 들어 있는지 확인합니다. 이 코스의 완성본 설정 파일에 들어 있는 값입니다.

    2. 작업 영역 설정 켜고 끄기: rust-analyzer.lens.enable

      설정 화면 검색창에 rust-analyzer.lens.enable을 입력하고 작업 영역 탭에서 체크를 끕니다. lab/lesson02/src/main.rs 탭으로 돌아가면 fn main() 위의 Run | Debug 링크가 사라집니다. 이제 .vscode/settings.json을 다시 열면 화면에서 바꾼 값이 "rust-analyzer.lens.enable": false처럼 JSON으로 기록된 것을 볼 수 있습니다. UI 체크박스는 결국 이 JSON 파일을 대신 편집해 주는 도구입니다. 확인이 끝나면 체크를 다시 켭니다. 그러면 Run | Debug 링크가 다시 나타납니다(JSON 항목이 true로 바뀌거나 사라질 수 있습니다).

    3. 사용자 설정과 터미널 프로필 읽기 (바꾸지 않습니다)

      설정 검색창에 terminal.integrated.defaultProfile.windows를 입력하고 사용자 탭에서 현재 값을 읽어 봅니다. 기본 프로필을 바꾸는 것은 모든 프로젝트에 영향을 주므로 이 코스에서는 바꾸지 않고, 필요할 때마다 터미널 목록(∨)에서 프로필을 골라 씁니다. 기본 프로필을 바꾸려면 명령 팔레트의 Terminal: Select Default Profile을 쓰며, VS Code는 이 명령이 설정을 terminal.integrated.defaultProfile.windows에 기록한다고 설명합니다.

    문제 1. 두 프로필의 도구 체인 점검표 만들기

    PowerShell 터미널과 MSYS2 bash 터미널 둘 다에서 rustc --version, cargo --version이 성공하게 만들고, 두 터미널의 출력 버전이 같은지 눈으로 비교합니다. 완료 조건: 두 프로필 모두 두 명령이 버전을 출력하고, 어느 프로필에서 PATH 보정이 필요했는지 말할 수 있습니다.

    힌트 보기

    bash에서 command not found가 나오면 3단계의 export 한 줄을 입력해 봅니다. 영구 적용은 ~/.bashrc에 같은 줄을 넣고 새 터미널을 여는 방법입니다. PowerShell만 쓰기로 했다면 bash는 확인만 하고 넘어가도 됩니다.

    정답 예시 보기 
    export PATH="$PATH:$(cygpath -u "$USERPROFILE")/.cargo/bin"
rustc --version
cargo --version

    PowerShell에서는 PATH 보정 없이 두 명령이 바로 성공해야 합니다.

    증상: PowerShell에서 rustc를 인식하지 못한다

    한국어 Windows에서는 다음과 같은 메시지가 나옵니다(앞에 rustc: 같은 접두어가 붙기도 합니다). rustup 설치 직후에 열어 둔 터미널과 VS Code는 갱신된 PATH를 모르기 때문에 생기는 경우가 많습니다. VS Code 공식 문서도 설치 후 터미널과 VS Code를 다시 시작하라고 안내합니다. 새로 시작해도 같다면 %USERPROFILE%\.cargo\bin이 PATH에 있는지 확인합니다.

    'rustc' 용어는 cmdlet, 함수, 스크립트 파일 또는 실행 프로그램의 이름으로 인식되지 않습니다.
이름의 철자를 확인하거나 경로가 포함되어 있으면 경로가 올바른지 확인하고 다시 시도합니다.

    증상: MSYS2 bash에서 cargo: 명령을 찾을 수 없음

    3단계에서 설명한 PATH 문제입니다. 임시로는 export PATH=…, 영구적으로는 ~/.bashrc에 한 줄을 추가하거나 PowerShell 프로필을 씁니다.

    bash: cargo: 명령을 찾을 수 없음

    cargo run이나 cargo check를 Cargo.toml이 없는 폴더에서 실행한 것입니다. 터미널 현재 위치가 D:\study\rust이면 cd lab으로 이동하세요.

    error: could not find `Cargo.toml` in `D:\study\rust` or any parent directory

    증상: 링커를 찾을 수 없다는 오류

    VS Code 공식 문서가 소개하는 대표 메시지는 error: linker `link.exe` not found입니다. MSVC 빌드 도구(C++ 워크로드)가 없을 때 나옵니다. 아래는 링커 이름을 일부러 틀리게 지정해서 재현한 같은 계열의 메시지이며, 따라 할 필요는 없습니다. 마지막 두 note가 MSVC 도구 설치를 안내하는 부분입니다. Visual Studio Build Tools 설치 프로그램에서 C++를 사용한 데스크톱 개발을 추가한 뒤 터미널을 다시 시작합니다.

    error: linker `no-such-linker` not found
  |
  = note: program not found

note: the msvc targets depend on the msvc linker but `link.exe` was not found

note: please ensure that Visual Studio 2017 or later, or Build Tools for Visual Studio were installed with the Visual C++ option

    증상: 터미널에서 rust-analyzer --version이 오류를 낸다

    rust-analyzer 구성요소를 rustup으로 설치하지 않았다면 Unknown binary 'rust-analyzer.exe' in official toolchain … 같은 오류가 나옵니다(이 PC에서 확인). .cargo\bin의 rust-analyzer.exe는 rustup이 만들어 둔 중계 프로그램일 뿐이기 때문입니다. VS Code 확장은 자신의 설치 폴더에 있는 서버를 쓰므로(공식 매뉴얼) 문제가 아닙니다. 확장이 동작하는지는 7단계의 인레이 힌트로 확인하세요.

    증상: rust-analyzer가 계속 로딩 중이거나 아무 기능이 없다

    폴더를 D:\study\rust로 열었는지, 상태 표시줄에 제한 모드(Restricted Mode) 배지가 없는지 확인합니다. 제한 모드에서는 확장 기능이 막힐 수 있으므로 Workspaces: Manage Workspace Trust 명령으로 폴더를 신뢰합니다. 그다음 rust-analyzer: Restart server를 실행합니다.

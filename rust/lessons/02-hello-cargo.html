    핵심 개념 한국어 요약

    cargo는 Rust의 빌드 도구이자 패키지 관리자이고, 테스트·포맷·린트까지 부르는 단일 진입점입니다. 프로젝트 하나를 패키지(package)라고 부르고, 패키지의 설정 파일이 Cargo.toml입니다. 패키지 안의 컴파일 단위는 크레이트(crate)입니다. src/main.rs는 실행 파일 크레이트의 시작점이고, src/bin/이름.rs를 만들면 실행 파일이 하나 더 생깁니다.

    fn main()이 프로그램의 시작 함수입니다. println!의 느낌표(!)는 이것이 함수가 아니라 매크로(macro)라는 표시입니다. 매크로는 컴파일할 때 코드로 펼쳐지고, println!은 문자열의 {} 자리표시자를 컴파일 시점에 검사합니다. 자리표시자 개수와 인자가 맞지 않으면 실행하기 전에 오류가 납니다.

    빌드에는 두 가지 프로필(profile)이 있습니다. cargo build는 debug 프로필로 컴파일이 빠르고 디버깅 정보를 담으며 결과가 target/debug에 생깁니다. cargo build --release는 release 프로필로 최적화를 켜고 target/release에 결과를 둡니다. cargo check는 실행 파일을 만들지 않고 타입과 소유권 검사만 해서 가장 빠릅니다. 이 레슨의 목표 가운데 하나는 코드를 고치고 저장할 때마다 이 검사를 자연스럽게 돌리는 것입니다.

    HANDS-ON따라하기

    앞 레슨에서 D:\study\rust를 열었고 터미널에서 cargo --version이 된다고 가정합니다(bash라면 레슨 01의 PATH 보정 필요). 코드 위의 파일 이름 막대(예: lab/lesson02/src/main.rs)는 완성본의 위치입니다. 완성본은 이미 lab 폴더에 들어 있으므로, 직접 입력할 때는 같은 폴더에 다른 이름의 새 파일을 만듭니다. 이 코스에서는 완성본 이름 앞에 my_를 붙입니다.

    1. 새 프로젝트 만들기: cargo new

      (앞 단계 없음) Ctrl+`로 터미널을 엽니다. 위치가 D:\study\rust인지 pwd로 확인한 뒤 연습용 프로젝트를 만듭니다. --vcs none은 Git 저장소를 따로 만들지 않는다는 뜻입니다.

      cargo new playground/hello_cargo --vcs none
          Creating binary (application) `hello_cargo` package
note: see more `Cargo.toml` keys and their definitions at https://doc.rust-lang.org/cargo/reference/manifest.html

      playground 폴더가 없으면 cargo가 함께 만듭니다. 패키지 이름은 마지막 폴더 이름(hello_cargo)이 됩니다.

    2. 만들어진 파일 읽기

      (1단계 이후) Ctrl+Shift+E로 탐색기를 열고 playground → hello_cargo를 펼칩니다. Cargo.toml을 한 번 클릭하면 탭이 열립니다. 이 폴더는 rust-analyzer가 읽는 프로젝트(lab)에 포함되지 않으므로 자동 완성은 되지 않고, 지금은 읽기만 합니다.

      [package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]

      name은 패키지 이름, version은 내 패키지의 버전, edition은 Rust 언어의 에디션(문법 세대)입니다. Rust 컴파일러 버전이 아닙니다. [dependencies] 아래에는 외부 크레이트를 적으며 Gradle의 dependencies {}에 해당합니다. 이어서 src/main.rs를 엽니다.

      fn main() {
    println!("Hello, world!");
}
    3. 실행해 보기: cargo run

      (1단계의 프로젝트 폴더에서) 터미널에서 프로젝트 안으로 들어가 실행합니다. 같은 명령을 한 번 더 실행하면 이번에는 컴파일 줄이 사라집니다. 바뀐 것이 없으면 다시 컴파일하지 않기 때문입니다.

    4. 검사와 릴리스 빌드: cargo check, cargo build --release

      (3단계와 같은 폴더에서) 두 명령을 차례로 실행하고, 출력의 대괄호 안 프로필 이름이 다른 것을 확인합니다.

      cargo check

      unoptimized + debuginfo는 debug 프로필, optimized는 release 프로필입니다. 이제 탐색기에서 target 폴더를 펼치면 debug와 release가 따로 있고 각각에 hello_cargo.exe가 있습니다. 직접 실행하려면 cargo run --release를 씁니다. target 폴더는 빌드 산출물이라 지워도 다시 만들어지고, Gradle의 build 폴더와 같습니다.

    6. 새 파일에 직접 입력하고 실행하기

      (5단계의 lab 터미널은 그대로 두고) 탐색기에서 lab/lesson02/src/bin 폴더를 우클릭해 새 파일을 고르고 my_main.rs를 입력한 뒤 Enter를 누릅니다. 에디터에서 아래 코드를 복사하지 말고 직접 입력해 보세요. 자동 완성 목록이 뜨면 방향키와 Enter로 고르는 것도 연습입니다. 입력을 마치면 Ctrl+S로 저장합니다.

    println!("안녕하세요, Rust!");

    let name = "Cargo";

    println!("{name}와 함께하는 {day}일차");

      서식 문자열을 하나씩 해석해 봅니다. {name}은 변수 이름을 직접 쓰는 방식이고, {}는 뒤의 인자를 순서대로 채웁니다. {0}은 번호로 같은 인자를 재사용합니다. {:>6}은 6칸 오른쪽 정렬, {:<6}은 왼쪽 정렬, {:^6}은 가운데 정렬이고, {price:.2}는 소수 둘째 자리까지 반올림합니다(12.3456이 12.35로 출력된 것을 확인하세요). {:?}는 디버그 출력, {:#?}는 줄을 나눠 보기 좋게 출력하는 형태입니다.

    7. 에디터 분할과 탭 이동

      (6단계에서 my_main.rs가 열려 있는 상태에서) Ctrl+\를 눌러 에디터를 둘로 나눕니다. 오른쪽 칸이 활성 상태일 때 탐색기에서 lab/lesson02/Cargo.toml을 클릭하면 오른쪽 칸에 열립니다. 이제 왼쪽에는 코드, 오른쪽에는 설정 파일이 나란히 보입니다. Ctrl+Tab을 누른 채로 Tab을 반복해 열린 파일 목록을 돌아 보고, 손을 떼면 그 파일로 이동합니다. Ctrl+P에 args를 입력해 args.rs를 열어도 파일 사이를 빠르게 오갈 수 있습니다. 활성 탭은 Ctrl+W로 닫습니다.

      [package]
name = "lesson02"
edition.workspace = true
version.workspace = true
publish.workspace = true
default-run = "lesson02"

[dependencies]

      edition.workspace = true는 lab/Cargo.toml의 [workspace.package]에 적힌 값을 물려받는다는 뜻입니다. 이 코스의 lab은 members = ["lesson*"]로 모든 레슨 크레이트를 한 워크스페이스로 묶어, cargo 명령 하나로 전체를 검사할 수 있게 합니다. Gradle의 settings.gradle.kts에서 include하는 것과 비슷합니다. default-run은 실행 파일이 여러 개일 때 --bin 없이 cargo run이 고를 파일 이름입니다.

    8. 저장 시 자동 정렬 체험하기

      (6단계의 my_main.rs 탭에서) 첫 줄 fn main() { 아래의 println! 줄 앞 공백을 지우거나 여러 칸으로 늘려 들여쓰기를 일부러 망가뜨립니다. Ctrl+S를 누르면 저장과 동시에 rustfmt가 4칸 들여쓰기로 되돌립니다. 이 코스의 작업 영역 설정이 Rust 파일에 저장 시 정렬을 켜 두었기 때문입니다. 저장 없이 지금 바로 정렬하려면 Shift+Alt+F를 누릅니다(문서 서식, Format Document). 터미널에서 같은 일은 아래 명령입니다.

      cargo fmt -p lesson02 -- --check

      모두 정렬돼 있으면 아무것도 출력하지 않고 끝납니다. --check를 빼면 파일을 직접 고칩니다. 규칙에 어긋난 파일이 있으면 어떻게 보이는지는 아래 "자주 나는 오류"에 실었습니다. 이 단계의 설정 조작은 "오늘의 VS Code 기능"에서 이어집니다.

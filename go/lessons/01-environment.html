    핵심 개념 한국어 요약

    Go 도구 체인(toolchain)은 go 명령 하나에 컴파일러, 실행, 테스트, 포맷터, 정적 검사, 모듈 관리가 모두 들어 있습니다. JDK, Gradle, ktlint, JUnit을 따로 맞추던 것과 달리 설치할 것이 하나입니다.

    GOROOT는 Go 자체가 설치된 폴더(표준 라이브러리 소스와 도구 포함)이고, GOPATH는 내려받은 모듈 캐시와 go install로 설치한 실행 파일(GOPATH\bin)이 쌓이는 폴더입니다. 모듈(module) 방식에서는 내 코드를 GOPATH 안에 둘 필요가 없습니다.

    언어 서버(Language Server)는 에디터와 분리된 분석 프로그램입니다. Go의 언어 서버가 gopls이고, 자동 완성, 정의로 이동, 오류 표시를 맡습니다. 디버거는 dlv(Delve)입니다. Go 확장은 이 도구들을 GOPATH\bin에 설치합니다. 공식 문서에 따르면 gopls가 없으면 확장이 설치를 시도하고, 나머지 도구는 Go: Install/Update Tools 명령으로 설치하거나 갱신합니다.

    작업 영역 신뢰(Workspace Trust)는 낯선 폴더의 코드를 VS Code가 마음대로 실행하지 못하게 하는 장치입니다. 신뢰하지 않으면 제한 모드(Restricted Mode)로 열리고, 공식 문서 기준으로 터미널, 태스크, 디버깅, 작업 영역 설정, 확장 기능이 제한됩니다. 즉 신뢰하지 않으면 이 코스의 실습이 대부분 동작하지 않습니다.

    go.work는 여러 모듈을 한 작업 영역으로 묶는 파일입니다. 이 코스 폴더에는 클론한 외부 저장소가 여러 개 있고 저마다 go.mod를 갖고 있습니다. 그래서 직접 작업하는 모듈은 lab 하나라고 go.work가 알려 줍니다.

    HANDS-ON따라하기

    단계는 앞 단계의 결과에 이어집니다. 이 레슨에는 직접 입력할 코드가 없고, 모든 명령은 PowerShell과 bash에서 같은 모양입니다(다른 경우만 따로 표시합니다). 터미널 출력의 사용자 이름이나 경로는 PC마다 다릅니다.

    1. 코스 폴더가 열려 있고 신뢰된 상태인지 확인하기

      레슨 00에서 폴더 열기와 신뢰, 권장 확장 설치까지 마쳤다면 이 단계는 상태만 확인하고 넘어갑니다. 아직 폴더가 열려 있지 않다면 VS Code에서 Ctrl+K Ctrl+O를 눌러 폴더 선택 창을 열고 D:\study\go를 선택한 뒤 폴더 선택을 누릅니다.

      확인: 왼쪽 탐색기(Ctrl+Shift+E)에 lab, lessons, go.work 같은 항목이 보이고, 창 위쪽에 제한 모드(Restricted Mode) 배너와 상태 표시줄의 제한 모드 배지가 모두 없어야 합니다. 배너나 배지가 보이면 아직 신뢰하지 않은 상태이므로 배너의 Manage 링크로 신뢰 화면을 열어 이 폴더를 신뢰합니다. "이 폴더의 작성자를 신뢰합니까?"라는 질문 창이 뜨면 Trust Folder & Continue(또는 Yes, I trust the authors) 버튼을 누르고, 부모 폴더 전체를 신뢰하는 체크 상자는 켜지 마세요.

    2. 통합 터미널 열고 PowerShell 터미널 만들기

      1단계에서 폴더를 연 상태에서 Ctrl+`를 눌러 터미널 패널을 엽니다(키보드에서 백틱을 누르기 어렵다면 명령 팔레트 Ctrl+Shift+P에서 Terminal: Create New Terminal을 실행합니다). 터미널 패널 오른쪽 위의 + 옆 화살표(⌄)를 눌러 프로필 목록을 보고 PowerShell 계열 프로필을 선택해 새 터미널을 엽니다.

      확인: 프롬프트가 PS로 시작하고 현재 폴더가 D:\study\go입니다. 터미널 패널 오른쪽의 탭 목록에 프로필 이름이 표시됩니다.

    3. go version과 go env 확인하기

      2단계의 PowerShell 터미널에 다음을 입력합니다.

      go version
go env GOROOT GOPATH GOOS GOARCH
      go version go1.27.0 windows/amd64
C:\Program Files\Go
C:\Users\사용자\go
windows
amd64

      첫 줄은 설치된 Go 버전과 운영체제/CPU 구조입니다. 이어지는 네 줄은 순서대로 GOROOT(Go 설치 폴더), GOPATH(모듈 캐시와 도구 설치 위치), GOOS, GOARCH입니다. 버전 숫자와 사용자 이름 부분은 다를 수 있습니다. go env에 변수 이름을 여러 개 주면 값만 한 줄씩 출력합니다.

    4. bash(MSYS2) 터미널에서 같은 명령 실행하기

      이번에는 같은 터미널 프로필 목록(⌄)에서 bash 계열(MSYS2) 프로필로 새 터미널을 엽니다. 프롬프트가 $로 끝나는 bash 모양이면 같은 명령을 입력합니다.

      pwd
go version

      MSYS2 bash는 Windows 경로를 /d/study/go 형태로 보여 줍니다. 그리고 로그인 셸(bash --login)로 시작하면 MSYS2가 PATH를 자기 기준으로 다시 만들기 때문에, 기본 설정에서는 Windows에 설치한 go를 찾지 못합니다. 이 PC의 MSYS2 프로필을 같은 방식(--login -i, MSYSTEM=UCRT64)으로 직접 실행해 확인한 결과입니다.

      /d/study/go
bash: go: 명령을 찾을 수 없음

      이 문제를 피하는 방법은 "설정 체험하기"에서 안전한 순서로 다룹니다. 가장 안전한 방법은 설정을 바꾸지 않고 터미널을 열 때마다 PowerShell 프로필을 고르는 것이며, 이 코스는 그 방법만으로 끝까지 진행할 수 있습니다. gopls, dlv 같은 도구도 PowerShell에서 먼저 확인하세요.

    5. 확장 탭에서 Go 확장 확인하고 설치하기

      Ctrl+Shift+X로 확장 탭을 엽니다. 위쪽 검색창에 @recommended를 입력하면 권장 확장 목록만 필터링됩니다. 이 코스 폴더의 .vscode/extensions.json이 알려 주는 작업 영역 권장 사항(Workspace Recommendations) 아래에 golang.go(이름 Go, 게시자 Go Team at Google)와 humao.rest-client가 보입니다. 레슨 00에서 이미 설치했다면 Installed(설치됨)로 표시되니 상세 화면에서 확장 ID가 golang.go인지만 확인합니다. 아직이라면 Go 확장의 Install(설치)을 누릅니다.

      목록에서 보이지 않으면 검색창을 지우고 golang.go를 입력해 찾습니다. 같은 일을 명령줄로 하려면 code --install-extension golang.go를 실행합니다. 이미 설치한 Java, Kotlin, Python 확장과는 서로 다른 언어를 맡으므로 그대로 두어도 됩니다.

    6. Go 파일을 열어 언어 서버와 도구 설치하기

      5단계에서 확장을 설치한 상태에서 Ctrl+P를 눌러 lesson02/main.go를 입력하고 엔터 키로 엽니다(레슨 02의 완성 코드입니다. 지금은 읽기만 합니다). .go 파일을 열면 확장이 활성화되고, 오른쪽 아래 상태 표시줄에 Go 버전이 나타납니다.

      화면 오른쪽 아래에 도구가 없다는 알림(Analysis Tools Missing)이 나오면 설치 버튼을 누릅니다. 알림이 없거나 놓쳤다면 Ctrl+Shift+P로 명령 팔레트를 열고 Go: Install/Update Tools를 실행해 목록에서 gopls와 dlv를 포함한 도구를 선택하고 확인합니다. 진행 로그는 출력 패널(Ctrl+Shift+U)에서 볼 수 있습니다.

      설치가 끝나면 PowerShell 터미널에서 확인합니다. 도구는 GOPATH\bin에 설치되므로, 그 폴더가 PATH에 있어야 터미널에서 이름만으로 실행됩니다.

      gopls version
dlv version
      golang.org/x/tools/gopls v0.24.0
Delve Debugger
Version: 1.27.2
Build: $Id: 360e7b2181d3da54115aaee4f569954bca95cfe3 $

      버전 숫자는 설치 시점과 확장 버전에 따라 다릅니다. 같은 파일에서 fmt.Println 위에 마우스를 올렸을 때 설명 팝업이 뜨고, 상태 표시줄의 Go 버전 옆에 번개 아이콘(⚡)이 보이면 gopls가 동작 중이라는 뜻입니다(공식 문서의 안내입니다).

    7. go.work와 작업 모듈 확인하기

      6단계의 PowerShell 터미널에서 lab 폴더로 이동한 뒤 확인합니다. 탐색기에서 go.work를 열어 주석과 use ./lab 줄도 읽어 봅니다.

      cd lab
go env GOWORK
go list -m
      D:\study\go\go.work
golab

      GOWORK는 go 명령이 현재 쓰는 go.work의 경로입니다. 현재 폴더에서 위로 올라가며 찾기 때문에 lab 안에서도 같은 파일이 잡힙니다. go list -m은 작업 영역의 모듈 이름 golab(lab/go.mod의 module golab)을 보여 줍니다. 이후 모든 레슨의 명령은 lab 폴더에서 실행합니다.

    클론한 자료 폴더는 읽기용입니다go-by-example, learn-go-with-tests, tour-of-go, 100-go-mistakes는 go.work에 없는 별개의 모듈입니다. 이 폴더들 안에서는 go 명령을 실행하지 마세요. 원문 예제를 따라 해 보고 싶으면 코드를 읽고 lab/lessonNN/mine 폴더에 직접 입력해서 실행합니다. GitHub에서 이 저장소를 새로 받았다면 이 폴더들은 없으니, 저장소 맨 위 README.md의 git clone 명령으로 받으세요. 받지 않아도 lab 실습은 진행됩니다.

    설정 체험하기

    사용자 설정은 백업한 뒤, 되돌릴 방법과 함께 바꿉니다아래 6단계 중 사용자 설정 파일을 바꾸는 것은 4번(기본 프로필)과 5번(MSYS2 환경 변수) 두 가지뿐입니다. 사용자 settings.json은 이 PC의 모든 VS Code 창에 적용되고 다른 설정이 이미 많이 들어 있을 수 있습니다. 바꾸기 전에 반드시 3번에서 백업 파일을 만드세요. 두 단계는 꼭 할 필요가 없습니다. 2번만으로 이 코스는 끝까지 진행할 수 있습니다.
    1. 기본 터미널 프로필 설정 읽어 보기 (설정 변경 없음)

      Ctrl+,로 설정 화면을 열고 검색창에 terminal.integrated.defaultProfile.windows를 입력합니다. 사용자 탭에서 현재 값(기본으로 여는 프로필 이름)을 확인하고 메모해 둡니다. 화면 오른쪽 위의 설정 열기(JSON) 아이콘을 누르면 같은 값이 settings.json에 "terminal.integrated.defaultProfile.windows": "프로필 이름" 형태로 적혀 있는 것을 볼 수 있습니다. 보기만 하고 아무것도 고치지 마세요.

    2. 가장 안전한 방법: 터미널을 열 때 PowerShell 고르기 (설정 변경 없음)

      터미널 패널의 + 옆 화살표(⌄)에서 PowerShell 프로필을 고르면 그 터미널 하나만 PowerShell로 열립니다. 어떤 설정 파일도 바뀌지 않습니다. 2단계에서 이미 해 본 방법이고, 이 코스의 모든 명령은 이 터미널에서 그대로 동작합니다. 기본 셸을 바꾸지 않은 채 필요할 때만 PowerShell을 쓰는 것이 가장 안전합니다.

    3. 사용자 settings.json 백업하기 (4번, 5번을 하기 전에 필수)

      Windows에서 사용자 설정 파일의 기본 위치는 %APPDATA%\Code\User\settings.json입니다(공식 문서). VS Code 프로필을 따로 만들어 쓴다면 %APPDATA%\Code\User\profiles\프로필 ID\settings.json처럼 경로가 다릅니다. 이 PC에는 첫 번째 위치에 파일이 있는 것을 확인했습니다. 아래 명령은 PowerShell 터미널에서 직접 실행합니다($env: 문법이라 bash에서는 동작하지 않습니다).

      먼저 이미 백업 파일이 있는지 확인합니다. False가 나와야 정상입니다. True가 나오면 예전 백업이 있다는 뜻이니 다음 복사를 하지 마세요. 복사 명령은 이미 있는 파일을 아무 경고 없이 덮어씁니다(임시 폴더로 같은 명령을 실행해 확인했습니다). 덮어쓰면 원래 설정의 백업을 잃습니다.

      Test-Path "$env:APPDATA\Code\User\settings.json.bak"
      False

      백업을 만들고 확인합니다. True가 나오면 백업이 만들어진 것입니다.

      Copy-Item "$env:APPDATA\Code\User\settings.json" "$env:APPDATA\Code\User\settings.json.bak"
Test-Path "$env:APPDATA\Code\User\settings.json.bak"
      True

      설정이 망가졌을 때의 복원 명령은 다음과 같습니다. 백업 파일로 설정 파일을 덮어씁니다. 복원한 뒤에는 새 터미널을 열어 기본 셸이 원래대로인지 확인합니다. 백업은 모든 확인이 끝나기 전까지 지우지 마세요.

      Copy-Item "$env:APPDATA\Code\User\settings.json.bak" "$env:APPDATA\Code\User\settings.json" -Force
    4. (선택) 기본 프로필을 PowerShell로 바꾸기

      3단계의 백업이 있는 상태에서만 합니다. 명령 팔레트(Ctrl+Shift+P)에서 Terminal: Select Default Profile을 실행하고 PowerShell 프로필을 고릅니다. 다시 settings.json을 보면 1단계의 값이 선택한 이름으로 바뀌어 있습니다. 이 설정은 사용자 설정이라 모든 프로젝트에 적용됩니다.

      되돌리는 방법: 같은 명령 Terminal: Select Default Profile을 다시 실행해 1단계에서 메모한 원래 프로필을 고릅니다. 그래도 이상하면 3단계의 복원 명령을 실행합니다.

    5. (선택·고급) bash(MSYS2)에서 go를 찾게 하기

      되도록 건너뛰고 2번의 PowerShell 프로필을 쓰세요. MSYS2 공식 문서는 다른 MSYS2 설치본, Cygwin, 컴파일러 도구 체인 같은 외부 프로그램을 PATH에 섞는 것을 지원하지 않으며 예상하지 못한 방식으로 깨질 수 있다고 경고합니다. 아래 방법은 bash에서 go를 찾게 해 주는 것을 이 PC에서 확인했지만(go version 출력 확인), Windows의 PATH 전체를 bash에 섞는 일이라 다른 도구와 충돌할 가능성이 있습니다.

      그래도 해 보고 싶다면 3단계의 백업이 있는 상태에서만 합니다. 명령 팔레트에서 Preferences: Open User Settings (JSON)을 실행합니다. terminal.integrated.profiles.windows 안에서 MSYS2 프로필을 찾아, 그 프로필의 env 객체 안에 아래 한 줄을 추가합니다(앞 항목 끝에 쉼표가 있어야 합니다). env가 없다면 프로필 안에 "env": { ... }를 새로 만들어 그 안에 넣습니다. 다른 항목은 건드리지 않습니다.

      "MSYS2_PATH_TYPE": "inherit"

      저장한 뒤 settings.json 탭에 빨간 물결 밑줄이 없는지 확인합니다(공식 문서: JSON 형식 오류는 편집기에 강조 표시됩니다). 밑줄이 보이면 추가한 줄을 지우거나 3단계의 복원 명령을 실행합니다. 문제가 없으면 이미 열려 있는 터미널에는 적용되지 않으니 새 bash 터미널(Ctrl+Shift+`)에서 go version을 다시 실행합니다.

      MSYS2_PATH_TYPE은 MSYS2가 Windows의 PATH를 얼마나 물려받을지 정하는 환경 변수이며 기본값은 minimal입니다. inherit로 바꾸면 모두 물려받습니다(MSYS2 공식 문서 (영문)의 PATH 항목). 되돌리는 방법: 추가한 한 줄(과 새로 만든 env)을 지우고 저장하거나 3단계의 복원 명령을 실행합니다.

    6. 작업 영역 신뢰 상태 보기

      명령 팔레트에서 Workspaces: Manage Workspace Trust를 실행하면 작업 영역 신뢰 편집기가 열리고, 신뢰한 폴더 목록과 이 폴더의 현재 신뢰 상태를 볼 수 있습니다. 부모 폴더를 신뢰 목록에 추가하면 그 아래 모든 폴더가 신뢰되므로, 낯선 코드를 내려받는 폴더는 따로 두는 것이 안전합니다.

    이 코스의 설정코스 폴더의 .vscode/settings.json에는 코스용 권장 설정이 이미 들어 있습니다. 위 설정은 사용자 범위이고, 그 파일은 작업 영역 범위입니다. 같은 키가 둘 다 있으면 작업 영역 값이 우선합니다. 자세한 우선순위는 레슨 10에서 다시 다룹니다.

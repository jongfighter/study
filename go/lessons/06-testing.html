    LESSON 06 · 테스트

    테스트와 table-driven 패턴

    Go 표준 도구만으로 테스트를 작성하고 실행합니다. go test, t.Errorf, table-driven 테스트와 서브테스트, 예제 테스트, 커버리지, 벤치마크 맛보기까지 실제 코드로 따라 합니다. VS Code의 멀티 커서와 찾기/바꾸기로 테스트 코드를 빠르게 다듬는 법도 익힙니다.

    • 소요 약 130분
    • 난이도 ★★★☆☆
    • 선행 레슨 05
    • 실습 폴더 lab/lesson06/mine (완성 코드: lab/lesson06)

    GOAL학습 목표

    • _test.go 파일과 TestXxx(t *testing.T) 함수를 만들고 go test로 실행해 통과와 실패 출력을 읽을 수 있다.
    • table-driven 테스트와 t.Run 서브테스트를 작성하고, -run으로 원하는 케이스만 실행할 수 있다.
    • errors.Is로 오류 값을 검증하고, Example 테스트와 Benchmark를 작성할 수 있다.
    • -cover와 -coverprofile로 커버리지를 확인하고, (cached) 결과와 -count=1의 의미를 설명할 수 있다.
    • 멀티 커서(Ctrl+D, Ctrl+Alt+↓, Alt+클릭)와 찾기/바꾸기(Ctrl+F, Ctrl+H)로 여러 곳을 한 번에 고칠 수 있다.

    핵심 개념 한국어 요약

    테스트 파일과 함수. 테스트는 테스트할 코드와 같은 폴더의 이름_test.go 파일에 씁니다. Test로 시작하고 그 뒤 첫 글자가 소문자가 아닌 함수(TestNormalize)가 테스트입니다. 별도 단언(assert) 라이브러리 없이 평범한 if로 검사하고, 틀리면 t.Errorf(실패로 기록하고 계속)나 t.Fatalf(기록하고 즉시 중단)를 호출합니다. 관례적으로 메시지는 "얻은 값(got)"과 "기대한 값(want)" 순서로 적습니다. go test ./경로는 패키지 단위로 실행하며, 결과가 같으면 (cached)로 이전 결과를 다시 보여 줍니다. 캐시를 무시하려면 -count=1을 붙입니다.

    table-driven 테스트와 서브테스트. 입력과 기대값을 구조체 슬라이스(표)로 나열하고, 하나의 반복문에서 t.Run(이름, func(t *testing.T) {...})로 케이스마다 서브테스트를 실행합니다. 케이스 추가가 표에 한 줄 더하는 일이 되고, 실패한 케이스의 이름이 출력에 나타납니다. 서브테스트 이름의 공백은 _로 바뀝니다. JUnit의 @ParameterizedTest, pytest의 parametrize에 해당합니다.

    Example과 Benchmark. ExampleXxx 함수의 끝에 // Output: 값 주석을 쓰면 실행 결과를 검증하는 동시에 문서 예제가 됩니다. BenchmarkXxx(b *testing.B)는 for b.Loop() { ... }로 측정할 코드를 반복하며(b.Loop는 Go 1.24부터), go test -bench .로 실행합니다. 벤치마크만 보려면 -run '^$'로 일반 테스트를 건너뜁니다.

    커버리지. go test -cover는 테스트가 실행한 구문의 비율을, -coverprofile 파일은 줄 단위 정보를 파일로 남깁니다. go tool cover -func 파일이 함수별 비율을 보여 줍니다. 100%가 목표가 아니라 "테스트가 닿지 않은 곳이 어디인가"를 찾는 도구입니다. 데이터 경쟁 검사 옵션 -race는 C 컴파일러(cgo)가 필요해서 이 PC(gcc 없음)에서는 사용할 수 없습니다.

    HANDS-ON따라하기

    완성 코드가 lab/lesson06에 있고, 직접 입력하는 코드는 lab/lesson06/mine 아래에 둡니다. 코드 블록 위쪽 파일 이름은 비교용 완성본의 위치입니다. 터미널은 모두 lab 폴더에서 실행하고, 각 단계는 앞 단계의 파일을 이어서 씁니다. 출력의 시간(0.2xxs)과 벤치마크 숫자는 PC마다 다릅니다.

    1. 테스트할 패키지 만들기

      탐색기(Ctrl+Shift+E)에서 lab/lesson06을 우클릭해 새 폴더 mine/titles를 만들고, 그 안에 새 파일 titles.go를 만들어 아래 코드를 입력합니다. 이 패키지는 Task API(레슨 08)에서 쓸 "제목 다듬기와 검증" 기능입니다. 앞뒤 공백을 지우고 연속 공백을 하나로 줄이며, 비었거나 50글자를 넘으면 오류를 돌려줍니다.

      // Package titles 는 Task 제목을 다듬고 검증합니다.
package titles

import (
	"errors"
	"strings"
	"unicode/utf8"
)

const MaxLength = 50

var (
	ErrEmpty   = errors.New("제목이 비어 있습니다")
	ErrTooLong = errors.New("제목이 너무 깁니다")
)

// Normalize 는 앞뒤 공백을 지우고 연속된 공백을 하나로 줄인 제목을 돌려줍니다.
func Normalize(raw string) (string, error) {
	title := strings.Join(strings.Fields(raw), " ")
	if title == "" {
		return "", ErrEmpty
	}
	if utf8.RuneCountInString(title) > MaxLength {
		return "", ErrTooLong
	}
	return title, nil
}

      strings.Fields는 공백 기준으로 단어를 나누고 strings.Join이 다시 공백 하나로 잇습니다. utf8.RuneCountInString은 바이트가 아니라 글자 수를 셉니다(레슨 03의 len("한글")이 6이었던 이유입니다). 이 단계에서는 실행할 일이 없습니다.

    2. 첫 테스트 작성하고 실행하기

      mine/titles 폴더에 새 파일 titles_test.go를 만들고 먼저 package titles만 쓴 뒤, 아래 함수를 입력합니다. import는 직접 쓰지 마세요. 저장(Ctrl+S)하면 testing 패키지 import가 자동으로 추가됩니다(레슨 02의 저장 시 import 정리).

      func TestNormalizeTrimsSpaces(t *testing.T) {
	got, err := Normalize("  장보기  ")
	if err != nil {
		t.Fatalf("예상하지 못한 오류: %v", err)
	}
	if got != "장보기" {
		t.Errorf("Normalize() = %q; %q 이어야 합니다", got, "장보기")
	}
}

      터미널(Ctrl+`)에서 lab 폴더 기준으로 실행합니다. 그다음 같은 명령에 -cover를 붙여 커버리지를 봅니다.

      go test ./lesson06/mine/titles

ok  	golab/lesson06/mine/titles	0.309s	coverage: 66.7% of statements

      통과하면 ok와 패키지 이름, 걸린 시간만 한 줄로 나옵니다. 커버리지가 66.7%인 것은 이 테스트가 정상 경로만 지나가고, 빈 제목과 너무 긴 제목으로 반환하는 두 줄에는 닿지 않았기 때문입니다.

    3. table-driven 테스트와 서브테스트로 바꾸기

      2단계의 같은 titles_test.go에서 첫 테스트 아래에 아래 함수를 입력합니다. 표(tests)의 케이스는 7개입니다. 케이스 줄은 멀티 커서로 다듬을 수 있으니 4단계에서 다시 손봅니다. 저장하면 errors와 strings import가 자동으로 추가됩니다.

      func TestNormalize(t *testing.T) {
	tests := []struct {
		name    string
		input   string
		want    string
		wantErr error
	}{
		{"앞뒤 공백", "  장보기  ", "장보기", nil},
		{"연속 공백", "Go   공부하기", "Go 공부하기", nil},
		{"탭과 줄바꿈", "a\tb\nc", "a b c", nil},
		{"빈 문자열", "", "", ErrEmpty},
		{"공백만", "   ", "", ErrEmpty},
		{"최대 길이", strings.Repeat("가", MaxLength), strings.Repeat("가", MaxLength), nil},
		{"너무 김", strings.Repeat("가", MaxLength+1), "", ErrTooLong},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			got, err := Normalize(tt.input)
			if !errors.Is(err, tt.wantErr) {
				t.Fatalf("오류 = %v; %v 이어야 합니다", err, tt.wantErr)
			}
			if got != tt.want {
				t.Errorf("Normalize(%q) = %q; %q 이어야 합니다", tt.input, got, tt.want)
			}
		})
	}
}

      -v(자세히) 옵션을 붙여 실행하면 서브테스트가 하나씩 보입니다.

    --- PASS: TestNormalize/연속_공백 (0.00s)

      TestNormalize/앞뒤_공백처럼 서브테스트 이름의 공백이 _로 바뀐 것을 확인하세요. 오류 검증은 errors.Is(err, tt.wantErr)로 했습니다. 오류가 없을 때(wantErr가 nil)는 err도 nil이어야 통과합니다. 이 상태에서 -cover를 실행하면 coverage: 100.0% of statements가 됩니다.

    4. 멀티 커서와 찾기/바꾸기로 테스트 코드 다듬기

      3단계의 titles_test.go에서 마우스 없이 다음을 차례로 해 봅니다. 각 실험이 끝나면 Ctrl+Z로 되돌려 파일 내용이 3단계 때와 같게 만듭니다. 이 실험 중에는 저장(Ctrl+S)하지 마세요. 저장하면 쓰지 않게 된 import를 정리 기능이 지워 버릴 수 있습니다. 예를 들어 아래 둘째 실험에서 케이스 7줄을 모두 주석 처리하면 strings를 쓰는 곳이 사라져서, 그 상태로 실행하면 "strings" imported and not used 오류가 납니다.

      • 같은 단어 한꺼번에 바꾸기: for _, tt := range tests의 tt에 커서를 놓고 Ctrl+D를 누르면 그 단어가 선택됩니다. Ctrl+D를 7번 더 눌러 아래의 tt 8곳을 모두 선택(커서 8개)한 뒤 tc를 입력하면 한 번에 바뀝니다. 이름을 바꾼 뒤에도 go test가 통과해야 합니다. 되돌릴 때는 tc 하나를 더블 클릭하고 Ctrl+Shift+L로 모든 tc를 선택해 tt를 입력해도 됩니다.
      • 세로로 커서 늘리기: 표의 첫 케이스 줄에서 Home 키로 { 앞에 커서를 놓고 Ctrl+Alt+↓를 6번 눌러 7개 케이스 줄 모두에 커서를 만든 뒤 // 를 입력합니다. 7줄이 한꺼번에 주석 처리됩니다. Ctrl+Alt+↑를 누르면 커서가 위에서부터 하나씩 줄어듭니다. Ctrl+Z로 되돌립니다. (그래픽 드라이버 단축키와 겹쳐 Ctrl+Alt+↓가 화면 회전 등으로 동작하면 아래 Alt+클릭을 쓰세요.)
      • 마우스로 커서 추가하기: 표의 빈 문자열 줄 끝을 클릭하고, 공백만 줄 끝을 Alt+클릭해 커서를 두 개로 만든 뒤 // 비어 있는 입력을 입력합니다. 두 줄에 같은 주석이 붙습니다. Ctrl+Z로 되돌립니다.
      • 줄 선택해서 복사하기: 너무 김 케이스 줄 안에 커서를 놓고 Ctrl+L로 줄 전체를 선택한 뒤, 선택한 상태에서 Shift+Alt+↓로 아래에 복사합니다(레슨 03에서 쓴 줄 복사입니다). 복사된 줄의 이름만 너무 김 2로 바꿔 새 케이스를 만들고 go test가 통과하는지 확인한 뒤, Ctrl+Shift+K로 그 줄을 지웁니다.
      • 찾기와 바꾸기: Ctrl+F로 찾기 창을 열고 공백을 입력하면 일치하는 개수(이 파일에서는 3개)가 표시됩니다. Ctrl+H로 바꾸기 입력 칸을 열어 스페이스를 넣고 모두 바꾸기 버튼을 누르면 케이스 이름이 한꺼번에 바뀝니다. Ctrl+Z로 되돌린 뒤 go test가 여전히 통과하는지 확인합니다.

    6. 일부러 실패시켜 실패 출력 읽기

      mine/titles/titles.go의 strings.Join(strings.Fields(raw), " ")에서 공백 " "를 쉼표 ","로 바꾸고 저장한 뒤 테스트를 실행합니다. 단어가 하나뿐인 첫 테스트는 통과하지만, 단어가 여러 개인 케이스와 Example이 실패합니다.

      go test ./lesson06/mine/titles

    --- FAIL: TestNormalize/연속_공백 (0.00s)
        titles_test.go:43: Normalize("Go   공부하기") = "Go,공부하기"; "Go 공부하기" 이어야 합니다
    --- FAIL: TestNormalize/탭과_줄바꿈 (0.00s)

--- FAIL: ExampleNormalize (0.00s)

      실패한 서브테스트 이름(TestNormalize/연속_공백), 실패 메시지가 가리키는 파일과 줄(titles_test.go:43), t.Errorf에 적은 메시지가 순서대로 보입니다. 메시지에 입력, 얻은 값, 기대값을 모두 넣어 두면 디버거 없이도 원인을 알 수 있습니다. 확인한 뒤 ","를 " "로 되돌려 통과시킵니다.

    7. 원하는 테스트만 실행하고 캐시 이해하기

      이 단계는 통과하는 코드에서 합니다. -run은 정규식이라, 서브테스트는 슬래시로 구분합니다. 아래처럼 일부만 적으면 이름에 그 글자가 들어간 테스트가 모두 실행됩니다. 두 번째 줄을 보면 TestNormalizeTrimsSpaces도 함께 실행되었는데, TestNormalize가 그 이름의 앞부분과 일치하기 때문입니다.

      go test -count=1 -v -run 'TestNormalize/공백만' ./lesson06/mine/titles
      === RUN   TestNormalizeTrimsSpaces

    PRACTICE연습 문제

    풀이는 lab/lesson06/mine/practice 폴더에서 하세요. 아래 함수를 그 폴더의 clamp.go에 복사하고(패키지 이름은 practice), 테스트 파일 clamp_test.go를 직접 작성합니다. 완성본은 lab/lesson06/practice에 있습니다.

    package practice

// Clamp 는 value 를 lo 이상 hi 이하 범위로 맞춰 돌려줍니다.
func Clamp(value, lo, hi int) int {
	if value < lo {
		return lo
	}
	if value > hi {
		return hi
	}
	return value
}

    문제 1. table-driven 테스트 작성하기

    Clamp를 검사하는 table-driven 테스트 TestClamp를 작성하세요. 완료 조건: 범위 안, 최솟값 아래, 최댓값 위, 경계값(lo와 hi 그대로), 음수 범위를 포함해 케이스가 5개 이상이고, t.Run으로 서브테스트 이름이 출력된다. go test -v -run 'TestClamp/최솟값' ./lesson06/mine/practice로 한 케이스만 실행되는 것을 확인한다.

    힌트 보기

    표의 구조체 필드는 name, value, lo, hi, want면 충분합니다. 케이스 이름은 서브테스트 이름이 되므로 "최솟값 아래"처럼 상황을 적습니다. 4단계에서 배운 Ctrl+L과 Shift+Alt+↓로 줄을 복사해 케이스를 늘리면 빠릅니다. 실패 메시지에는 입력 세 값, 얻은 값, 기대값을 모두 넣으세요.

    정답 예시 보기 
    func TestClamp(t *testing.T) {
	tests := []struct {
		name  string
		value int
		lo    int
		hi    int
		want  int
	}{
		{"범위 안", 5, 0, 10, 5},
		{"최솟값 아래", -3, 0, 10, 0},
		{"최댓값 위", 42, 0, 10, 10},
		{"경계값 lo", 0, 0, 10, 0},
		{"경계값 hi", 10, 0, 10, 10},
		{"음수 범위", -5, -10, -1, -5},
	}

	for _, tt := range tests {
		t.Run(tt.name, func(t *testing.T) {
			if got := Clamp(tt.value, tt.lo, tt.hi); got != tt.want {
				t.Errorf("Clamp(%d, %d, %d) = %d; %d 이어야 합니다", tt.value, tt.lo, tt.hi, got, tt.want)
			}
		})
	}
}

    핵심 개념 한국어 요약

    패키지(package)와 진입점. 모든 Go 파일은 package 이름으로 시작합니다. 이름이 main인 패키지 안의 func main()이 프로그램의 시작점이고, 다른 이름의 패키지는 라이브러리입니다. 폴더 하나가 패키지 하나이고, 같은 폴더의 .go 파일은 모두 같은 패키지에 속합니다.

    모듈(module). go.mod가 있는 폴더 아래 전체가 하나의 모듈입니다. go.mod의 module 줄이 모듈 이름이고, 패키지를 가져오는 import 경로는 모듈 이름 + 폴더 경로입니다. 이 코스의 모듈은 golab이라서 lab/lesson02/greet 폴더의 패키지는 golab/lesson02/greet로 import합니다. go 1.24 줄은 이 모듈이 요구하는 Go 버전입니다.

    공개 규칙. public, private 같은 키워드가 없습니다. 이름이 대문자로 시작하면 패키지 밖에서 쓸 수 있고(exported), 소문자로 시작하면 패키지 안에서만 쓸 수 있습니다.

    go 명령. go run은 컴파일해서 임시로 실행하고 파일을 남기지 않습니다. go build는 실행 파일을 만듭니다. go fmt(와 gofmt)는 표준 서식으로 코드를 정렬하고, go vet은 컴파일은 되지만 의심스러운 코드(예: 형식 문자열과 인자 타입 불일치)를 찾습니다. 서식은 설정할 수 없고 하나뿐이라 서식 논쟁이 없습니다. 들여쓰기는 탭입니다.

    사용하지 않는 import는 컴파일 오류입니다. 변수도 선언만 하고 쓰지 않으면 오류입니다. 처음에는 불편하지만 에디터가 저장할 때 import를 자동으로 정리해 줍니다.

    2. 첫 파일 만들고 직접 입력하기

      방금 만든 mine 폴더를 우클릭해 새 파일(New File)을 선택하고 main.go를 입력합니다. 에디터에 빈 파일이 열리면 아래 코드를 복사하지 말고 직접 입력합니다. 입력하는 동안 fmt.까지 치면 나오는 자동 완성 목록을 살펴봅니다.

      안녕하세요, Go!

      ./lesson02/mine은 파일이 아니라 패키지가 있는 폴더를 가리킵니다. 같은 폴더에 .go 파일이 여러 개 있어도 폴더 단위로 컴파일됩니다.

    4. go.mod 읽고 새 모듈 만들어 보기

      탐색기에서 lab/go.mod를 열어 봅니다. 이 파일은 코스 전체가 쓰는 모듈 정의입니다.

      module golab

go 1.24

      이 코스의 모듈은 lab/go.mod 하나이고 이미 만들어져 있으므로, lab 안에서 go mod init을 다시 실행할 일은 없습니다. 새 모듈이 어떻게 만들어지는지 실험하고 싶다면 3단계의 터미널에서 코스 폴더 밖에 연습용 모듈을 만듭니다. 코스 폴더 안에 만들면 go.work 때문에 go run이 막히므로(아래 "자주 나는 오류"에서 실제 오류를 확인합니다) 반드시 D:\study 바로 아래에 만듭니다.

    5. 두 번째 패키지 만들고 import하기, 에디터 나누기

      탐색기에서 mine 폴더를 우클릭해 새 폴더 greet를 만들고, 그 안에 새 파일 greet.go를 만들어 아래 코드를 입력합니다. 이 파일의 패키지 이름은 폴더 이름과 같은 greet입니다.

      // Package greet 는 인사말을 만드는 작은 패키지입니다.
package greet

import "fmt"

// Hello 는 이름을 받아 인사말을 돌려줍니다.
// 이름이 대문자로 시작하므로 다른 패키지에서 greet.Hello 로 쓸 수 있습니다.
func Hello(name string) string {
	return decorate(fmt.Sprintf("%s님, 환영합니다", name))
}

// decorate 는 소문자로 시작하므로 greet 패키지 안에서만 쓸 수 있습니다.
func decorate(text string) string {
	return "** " + text + " **"
}

      이어서 mine/main.go를 아래 모양으로 고칩니다. 이 코드는 lab/lesson02/main.go와 같지만, 내 코드의 import 경로에는 mine이 한 단계 더 들어갑니다. 즉 golab/lesson02/greet 대신 아래 한 줄을 씁니다.

      "golab/lesson02/mine/greet"
      package main

import (
	"fmt"

	"golab/lesson02/greet"
)

func main() {
	fmt.Println("안녕하세요, Go!")
	fmt.Println(greet.Hello("Kotlin 개발자"))
}

      두 파일을 번갈아 보며 쓰려면 greet.go 탭을 연 상태에서 Ctrl+\로 에디터를 오른쪽으로 나눕니다. 같은 파일이 양쪽에 열리면 Ctrl+P로 main.go를 열어 한쪽을 바꾸고, Ctrl+Tab으로 열린 탭을 순서대로 오가 보세요. 더 이상 필요 없는 탭은 Ctrl+W로 닫습니다.

      실행합니다. 터미널의 현재 폴더는 lab이어야 합니다.

      go run ./lesson02/mine
      안녕하세요, Go!
** Kotlin 개발자님, 환영합니다 **

      두 번째 줄의 ** 장식은 greet 패키지 안의 소문자 함수 decorate가 붙인 것입니다. 이 함수는 밖에서 호출할 수 없습니다.

    6. go build, go vet, gofmt 써 보기

      5단계의 터미널에서 실행 파일을 만들고, 만든 파일을 직접 실행한 뒤, 점검 명령 두 개를 실행합니다. go vet과 gofmt -l은 문제가 없으면 아무것도 출력하지 않습니다. gofmt -l은 서식이 다른 파일 이름만 나열합니다.

      go build -o bin/hello.exe ./lesson02/mine
./bin/hello.exe
go vet ./lesson02/...
gofmt -l lesson02
      안녕하세요, Go!
** Kotlin 개발자님, 환영합니다 **

      아무 출력도 없는 것이 정상입니다. 출력이 나왔다면 파일 이름이 출력된 것이니 그 파일을 열어 저장(Ctrl+S)하면 정리됩니다. lab/bin 폴더는 .gitignore에 들어 있어 커밋되지 않으며, 확인 후 rm -r bin으로 지워도 됩니다. -o 없이 go build ./lesson02/mine을 실행하면 현재 폴더에 mine.exe가 생깁니다. -o bin/hello처럼 확장자 없이 쓰면 확장자 없는 파일이 만들어지므로(이 PC에서 확인했습니다) Windows에서는 .exe를 직접 붙였습니다.

      확인: 프로그램 출력 안녕하세요, Go!와 인사말 줄이 디버그 콘솔(Ctrl+Shift+Y)에 나타납니다. 구성의 console 기본값이 내부 콘솔이기 때문이며, 출력 앞뒤로 디버거 시작·종료 메시지가 함께 보일 수 있습니다. 터미널에서 go run으로 실행한 결과와 줄 내용이 같으면 성공입니다. 지금 단계는 중단점 없이 실행만 해 봅니다. 중단점은 레슨 07에서 다룹니다.

    설정 체험하기

    1. 저장 시 포맷 설정 끄고 켜 보기

      Ctrl+,로 설정 화면을 열고 검색창에 @lang:go editor.formatOnSave를 입력합니다. 작업 영역(Workspace) 탭을 선택하면 Go 언어에만 적용되는 Editor: Format On Save가 체크되어 있습니다. 이 코스의 .vscode/settings.json이 켜 둔 값입니다. Go 확장도 Go 파일에 대해 기본으로 이 설정을 켭니다(확장 문서 기준).

      체크를 끈 뒤 mine/main.go에서 fmt.Println 줄의 들여쓰기를 지워 왼쪽 끝으로 붙이고 저장합니다(Ctrl+S). 이번에는 들여쓰기가 그대로 남습니다. Shift+Alt+F(문서 서식)를 누르면 그제서야 정리됩니다. 서식 정리와 import 정리는 별개의 저장 동작이라서, import에 쓰지 않는 "os"를 추가하고 저장하면 서식 설정과 상관없이 "os" 줄은 사라집니다(source.organizeImports 설정이 따로 켜져 있기 때문입니다).

      이제 체크를 다시 켜고 들여쓰기를 다시 망가뜨린 뒤 저장하면 이번에는 저장만으로 정리됩니다. .vscode/settings.json을 열어 "[go]" 묶음 안에 "editor.formatOnSave"가 어떻게 기록되는지 확인합니다. 설정 화면에서 바꾼 값은 이렇게 파일에 그대로 기록됩니다. 실험이 끝났을 때 값이 true로 돌아와 있어야 합니다.

    2. 다시 한 번, 빠진 import 채우기

      import "fmt" 줄을 통째로 지우고 저장해 보세요. fmt가 정의되지 않았다는 빨간 밑줄이 있었다면, 저장 후 다시 import 줄이 생깁니다. 공식 도구 gopls의 import 정리가 표준 라이브러리 패키지는 알아서 찾아 채워 주기 때문입니다. 이 동작이 "source.organizeImports": "explicit" 설정입니다(explicit은 저장 같은 명시적 동작에서만 실행한다는 뜻입니다).

    PRACTICE연습 문제

    문제 1. 이름을 명령줄 인자로 받기

    lab/lesson02/mine/practice 폴더에 main.go를 새로 만들어, go run ./lesson02/mine/practice 길동처럼 실행하면 길동에게 인사하게 하세요. 인자가 없으면 이름을 개발자로 합니다. 완료 조건: 인자가 있을 때와 없을 때 모두 인사 줄이 정답 예시의 첫 줄과 같고(작별 인사 줄은 문제 2에서 추가합니다), go vet이 아무 출력도 하지 않는다. (인사 함수는 이미 만든 greet 패키지를 쓰되, import 경로의 mine을 잊지 마세요.)

    힌트 보기

    프로그램에 넘긴 인자는 os 패키지의 os.Args에 문자열 슬라이스로 들어 있습니다. os.Args[0]은 프로그램 자신이고 첫 번째 인자는 os.Args[1]입니다. 인자 개수는 len(os.Args)로 확인합니다. if 문은 레슨 03에서 정식으로 배우지만, 조건에 괄호를 쓰지 않는다는 점만 알면 됩니다.

    정답 예시 보기 
    package main

import (
	"fmt"
	"os"

	"golab/lesson02/greet"
)

func main() {
	name := "개발자"
	if len(os.Args) > 1 {
		name = os.Args[1]
	}
	fmt.Println(greet.Hello(name))
	fmt.Println(greet.Farewell(name))
}

    완성 코드의 import 경로는 golab/lesson02/greet입니다. 내 코드는 mine 경로로 바꿔 쓰세요. 인자 없이 실행한 결과와 길동을 준 결과입니다(이 결과에는 문제 2의 Farewell 줄도 포함됩니다).

    ** 개발자님, 환영합니다 **
** 개발자님, 다음에 또 만나요 **
    ** 길동님, 환영합니다 **
** 길동님, 다음에 또 만나요 **

    문제 2. greet 패키지에 파일 하나 더 추가하기

    mine/greet 폴더에 farewell.go 파일을 만들어 작별 인사 함수 Farewell(name string) string을 추가하고, 문제 1의 프로그램이 인사 뒤에 작별 인사도 출력하게 하세요. 완료 조건: 같은 패키지의 파일이 둘로 나뉘어도 import는 그대로이고, 위 정답 예시와 같은 두 줄이 나온다.

    힌트 보기

    같은 폴더의 파일은 같은 패키지이므로 package greet로 시작하고, 서로의 소문자 함수(decorate)도 그대로 쓸 수 있습니다. Hello를 복사해서 문구만 바꾸면 됩니다. 이름이 대문자 F로 시작해야 main에서 호출할 수 있습니다.

    정답 예시 보기 
    package greet

import "fmt"

// Farewell 는 작별 인사를 돌려줍니다.
func Farewell(name string) string {
	return decorate(fmt.Sprintf("%s님, 다음에 또 만나요", name))
}

    FIX자주 나는 오류

    아래 오류 출력은 5단계까지 완성한 mine/main.go(와 mine/greet)를 각 항목에 적힌 대로 고친 뒤 lab 폴더에서 실행한 결과입니다. 파일 경로 앞부분, 줄·열 번호, 오류 개수는 내 파일이 조금만 달라도 달라질 수 있으니 메시지 문장을 중심으로 읽으세요.

    증상: import한 패키지를 쓰지 않았다는 오류

    원인은 import에 적은 패키지를 코드에서 쓰지 않은 것입니다. 아래는 mine/main.go의 import 목록에서 "fmt" 아래에 "os"를 한 줄 추가한 채 go run ./lesson02/mine을 실행했을 때의 출력입니다. 쓰지 않을 패키지의 줄을 지우면 해결됩니다. 저장 시 import 정리(source.organizeImports)가 켜진 상태에서 저장하면 이 줄은 자동으로 지워지므로, VS Code에서는 이 오류를 보기 어렵습니다.

    # golab/lesson02/mine
lesson02\mine\main.go:5:2: "os" imported and not used

    증상: 방금 쓴 import 줄이 저장하면 사라진다

    오류 메시지는 없습니다. 아직 코드에서 쓰지 않은 import는 저장할 때 import 정리가 지워 버리기 때문입니다. 코드를 먼저 쓰고(fmt.Println을 먼저 입력) 저장하면 import가 자동으로 채워집니다. 또는 자동 완성 목록에서 패키지 함수를 고르면 import가 함께 추가됩니다.

    증상: 소문자로 시작하는 이름을 다른 패키지에서 불렀다

    greet.decorate처럼 소문자로 시작하는 이름은 패키지 밖에서 쓸 수 없습니다. 아래는 mine/main.go의 마지막 줄 greet.Hello("Kotlin 개발자")를 greet.decorate("Kotlin 개발자")로 바꿔 실행했을 때의 출력입니다. 밖에서 쓰고 싶으면 이름을 대문자로 시작하게 바꿉니다(Decorate).

    # golab/lesson02/mine
lesson02\mine\main.go:11:20: name decorate not exported by package greet

    증상: 패키지를 찾을 수 없다

    import 경로의 철자나 폴더 위치가 틀렸습니다. 이 예는 mine/main.go의 import 경로 golab/lesson02/mine/greet를 golab/lesson02/mine/greeter로 잘못 적은 경우입니다. 오류 끝의 괄호는 Go가 표준 라이브러리 폴더에서 찾으려 한 위치이며, 경로는 PC마다 다릅니다. 폴더 이름과 모듈 이름(golab), mine 경로를 다시 확인하세요.

    lesson02\mine\main.go:6:2: package golab/lesson02/mine/greeter is not in std (C:\Program Files\Go\src\golab\lesson02\mine\greeter)

    증상: main 패키지가 아니라는 오류

    go run으로 실행할 폴더의 파일은 package main으로 시작하고 func main()이 있어야 합니다. 이 예는 mine/main.go의 첫 줄 package main을 package hello로 바꿨을 때입니다.

    package golab/lesson02/mine is not a main package

    증상: go vet이 형식 문자열 문제를 알려 준다

    go build는 통과하지만 go vet이 잡는 오류입니다. %d는 정수용인데 문자열을 넘겼습니다. 아래는 mine/main.go의 fmt.Println("안녕하세요, Go!") 줄을 fmt.Printf("%d\n", "안녕")으로 바꾸고 go vet ./lesson02/mine을 실행했을 때의 출력이고, go build는 이 상태에서도 오류 없이 끝납니다. 형식 지시자를 %s로 고칩니다.

    lesson02\mine\main.go:10:14: fmt.Printf format %d has arg "안녕" of wrong type string

    증상: 코스 폴더 안에 새로 만든 모듈에서 go run이 막힌다

    코스 폴더(D:\study\go) 안에서 go mod init으로 새 모듈을 만들면 그 모듈은 go.work의 use 목록(./lab뿐)에 없어서 실행이 거부됩니다. 오류는 만든 위치에 따라 두 가지입니다. 먼저 lab 밖(예: 코스 폴더 바로 아래의 scratch)에서 go run .을 실행했을 때입니다. 같은 구조로 재현한 실제 출력입니다.

    current directory is contained in a module that is not one of the workspace modules listed in go.work. You can add the module to the workspace using:
	go work use .

    다음은 lab 안(예: lab/lesson02/scratch)에 go mod init을 한 경우입니다. 중첩된 폴더에 go.mod가 생기면 그 폴더는 golab 모듈에서 빠지므로, 같은 실행 명령이 다른 오류를 냅니다. 이 경우에도 go work use 안내를 따르지 마세요. go.mod를 지우거나 폴더를 lab 밖으로 옮기면 됩니다.

    main module (golab) does not contain package golab/lesson02/scratch

    새 모듈 실험은 4단계처럼 코스 폴더 밖에서 하고, 코스 안의 실습 코드는 lab/lessonNN/mine 같은 폴더에 모듈 파일 없이 만듭니다.

    증상: go run . 이 파일이 없다고 한다

    lab 폴더 바로 아래에는 .go 파일이 없습니다. go run 뒤에 패키지가 있는 폴더(./lesson02/mine)를 적어야 합니다. 아래는 lab 폴더에서 go run .을 실행한 실제 출력이고, 경로는 내 PC의 lab 폴더 위치로 나옵니다.

    no Go files in D:\study\go\lab
